# Issue 03: PropertyBankDiscovery entry -> FsFile

**Parent:** `.scratch/property-bank-processor-deepening/PRD.md` (Supporting change)

## What to build

Change `PropertyBankDiscovery` so its `entry` field is `FsFile` instead of `FsEntry`. All callers get a compile-time guarantee that the discovery result is a file, with no runtime `.as_file()` check.

- `PropertyBankDiscovery.entry: FsEntry` → `FsFile`
- `PropertyBankDiscovery.entry()` returns `&FsFile` — no `Option::unwrap` or `.as_file()` needed
- Builder path removes `bank_discovery.entry().as_file()` and uses `bank_discovery.entry().metadata()` directly

## Acceptance criteria

- [ ] `PropertyBankDiscovery.entry` is `FsFile` (not `FsEntry`)
- [ ] `PropertyBankDiscovery.entry()` returns `&FsFile` (not `Option<&FsFile>`)
- [ ] No `.as_file()` call exists in any property-bank builder code path
- [ ] Property-bank load path no longer maps impossible runtime branch (`"property bank entry must be a file"`)
- [ ] Discovery and builder tests pass with compile-time file guarantee preserved

## Blocked by

- None (Issue 01 already merged to `main`)

## Implementation notes

- `FsFile` already exists in the codebase; no new type required
- `PropertyBankDiscovery` is the **only** type that uses `FsEntry` at this boundary
- `FsEntry::as_file()` → `Option<&FsFile>` — this was the runtime check; after this change it's `&FsFile` directly
- `DiscoveryEngine::run()` already constructs `PropertyBankDiscovery` with a file — it just needs to wrap `FsFile` instead of `FsEntry`
- Keep rooted key derivation path unchanged (`file.path().as_key(spec.root())`), preserving FS context invariants

## Test

Add/update focused unit tests in `schema::discovery` and `schema::builder` to assert compile-time file guarantees and unchanged behavior under create/update paths.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Strengthen schema discovery contract so property-bank discovery always carries a file-typed entry (`FsFile`) instead of a generic filesystem entry.

**Current behavior:**
The property-bank discovery payload exposes a generic entry type, requiring downstream code to re-check that the entry is a file via `as_file()` even though discovery classification already guarantees that only file entries are eligible for the property-bank slot.

**Desired behavior:**
The property-bank discovery payload should expose a file-typed entry directly. Downstream property-bank loading should consume file metadata/path without optional downcasts or impossible runtime error branches for non-file variants.

**Key interfaces:**
- `PropertyBankDiscovery` entry field and accessor should be file-typed
- Discovery classification step that selects the property-bank candidate should keep producing file-scoped entries for that branch
- Property-bank builder load path should consume file metadata/path directly from the typed discovery entry

**Acceptance criteria:**
- [ ] `PropertyBankDiscovery` stores a file-typed entry and accessor returns file type directly
- [ ] Property-bank builder path removes runtime file downcast checks for discovery entry
- [ ] Property-bank builder path no longer emits/depends on impossible "entry must be a file" runtime error branch
- [ ] Existing property-bank discovery/load behavior remains unchanged for valid inputs
- [ ] Targeted unit tests in discovery/builder pass and reflect new type-level contract

**Out of scope:**
- Changes to schema discovery payload typing for non-property-bank schema entries
- New filesystem entry variants or scanner behavior changes
- Repository/storage schema changes
