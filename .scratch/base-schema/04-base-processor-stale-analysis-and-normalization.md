## What to build

Implement stale-content parsing and semantic delta analysis for base schemas, including metadata-only normalization rules.

This slice adds `Parsed`/`Analysis`/`Refresh` behavior so timestamp/content drift without semantic changes emits `Fresh`, while semantic changes emit `Stale` with explicit deltas.

## Acceptance criteria

- [ ] Processor implements parsed stale path and property/excludes/extends diff analysis.
- [ ] `StaleTimestamps` and `StaleContent` normalize to `Fresh` when semantic state is unchanged.
- [ ] Semantic changes emit `Stale` with explicit `PropertyDelta`, `ExcludesDelta`, and `ExtendsDelta`.
- [ ] Full rebuild fallback triggers are implemented for parse/view corruption and incoherent delta results.
- [ ] `Fresh`/`Stale` outcomes preserve deterministic behavior across repeated runs.
- [ ] Unit tests cover stale-timestamp match, stale-content-no-semantic-change, semantic-delta, and corrupt fallback branches.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Extend `BaseSchemaProcessor` with `Comparison`/`Parsed`/`Analysis`/`Refresh` stages; normalize `StaleTimestamps`/`StaleContent` to `Fresh`; emit `Stale` with explicit deltas on semantic change.

**Current behavior:**
`BaseSchemaProcessor<Init, Unknown>::run()` handles two paths: missing view (constructs + persists a new `BaseSchema`) and present view (timestamp-match → `Fresh`). When timestamps do not match, the current implementation reconstructs from scratch and returns `New` — no stale analysis, no content hashing, no delta computation, and no `Stale` resolution variant exists. The `_source: &FileReader` parameter is unused. `BaseSchemaResolution` is `#[non_exhaustive]` but only carries `Fresh` and `New` variants.

**Desired behavior:**
The full staleness pipeline from `PropertyBankProcessor` must be mirrored for base schemas:

1. **Timestamp mismatch** → read file content, hash it, compare against view's stored content hash (`RawSchemaView::is_content_match`).
2. **Content match** (`StaleTimestamps`) → update view metadata, persist, return `Fresh`.
3. **Content mismatch** (`Stale`) → parse `RawSchema` from content, compare property hashes via `PropertyDeltaEngine::for_schema`, compare `excludes` via `ExcludesDelta::from_slices`, compare `extends` via `ExtendsDelta::from_slices`.
4. **No semantic delta** (`StaleContent`) → update view metadata + content hash, persist, return `Fresh`.
5. **Semantic delta** → persist updated `BaseSchema` + view (new `SchemaVersion` via `RawSchemaView::try_from_raw_with_hashes`), return new `Stale { schema_id, base_schema, property_delta, excludes_delta, extends_delta }` resolution variant.
6. **Corrupt view** (missing `current()` version) → full rebuild path, return `New`.

`BaseSchemaResolution` must gain a `Stale` variant carrying all three deltas. The `run()` doc comment must be updated to describe the full pipeline. The `_source` parameter must be used for content reading. The dead-code suppression on `Construction<Fresh>::fetch()` must be lifted.

**Key interfaces:**
- `BaseSchemaProcessor<Init, Unknown>::run()` — extend to invoke content read + hash comparison when timestamps mismatch; currently only timestamp-checks.
- `BaseSchemaResolution` — add `Stale { schema_id: SchemaId, base_schema: BaseSchema, property_delta: PropertyDelta, excludes_delta: ExcludesDelta, extends_delta: ExtendsDelta }` variant.
- New internal typestate statuses (mirroring `PropertyBankProcessor`): `Suspect { view: RawSchemaView, content: String }`, `Stale { content: String, content_hash: Blake3Hash, view: RawSchemaView }`, `StaleTimestamps { view: RawSchemaView }`, `StaleContent { view: RawSchemaView, content_hash: Blake3Hash }`, `ParsedStale { raw: RawSchema, content_hash: Blake3Hash, view: RawSchemaView }`.
- New stages: `Comparison` (timestamp + content hash checks), `Parsed` (parse `RawSchema`), `Analysis` (compute property/excludes/extends deltas), `Refresh` (persist metadata-only changes).
- `PropertyDeltaEngine::for_schema()` — already exists in `delta.rs`; used to compute property delta from `RawSchema` + previous property hash index.
- `ExcludesDelta::from_slices()` — already exists; compare old `SchemaVersion::excludes()` vs new `RawSchema::excludes()`.
- `ExtendsDelta::from_slices()` — already exists; compare old `SchemaVersion::extends()` vs new `RawSchema::extends()`.
- `SchemaVersion::new(metadata, hashes, &raw)` — already exists; used in `RawSchemaView::try_from_raw_with_hashes` to produce a new view version on the `Stale` path.
- `RawViewRead::update_content_hash()` — already exists on `RawSchemaView`; used in `Refresh` stage.
- `WriteRepository::save_raw_schema_view(id, &view)` — already exists; used to persist updated view on both `Refresh` paths.
- `WriteRepository::save_base_schema(&base)` — already exists; used on `Stale` path to persist updated `BaseSchema`.
- `RefExpander` — needed for `PropertyDeltaEngine::diff_schema(expander)`. The `RefExpander` must be supplied by the caller or constructed from the current `PropertyBank` (fetch via `repository.get_property_bank()`). This is the main new dependency.

**Acceptance criteria:**

**Approved clarifications:**
- `RefExpander::new(bank)` exists. It may have intentionally narrow visibility; prefer using the existing constructor without broadening visibility unless the compiler requires it. If visibility changes are required, keep them as narrow as possible and document why.
- Stale updates must reuse the existing `SchemaId`; do not generate a new schema identity for the stale path.
- Since `FileReader` is now used by `run()`, rename `_source` to `source`.
- If no `PropertyBank` is persisted and the schema has `$ref` properties, emit a tracing log and treat the referenced properties as empty/unexpanded. A full rebuild does not resolve the missing-bank condition.

**Implementation notes:**
- The `RefExpander` dependency is the most important design decision: fetch `PropertyBank` from repository at the start of `run()` (or lazily on the stale path). If the bank is missing and the schema contains `$ref` properties, log via tracing and proceed with empty/unexpanded ref-derived properties rather than escalating to full rebuild.
- `FileReader::parse_structured_from_str` parses `RawSchema` — use this (as in `PropertyBankProcessor`).
- Compute content hash with `Blake3Hash::compute(content.as_bytes())`.
- Compute property hashes using `PropertyDeltaEngine::for_schema(&raw, version.hashes().properties()).diff_schema(&expander)`.
- On the `Stale` resolution path, build a fresh `HashRecord` from new content hash + new property hashes, then call `RawSchemaView::try_from_raw_with_hashes(&raw, path_key, hash_record)` to create an updated view.
- The `#[expect(dead_code)]` suppression on the whole module (line 12–16 of current `base_processor.rs`) should be narrowed or removed as stages become active.

**Preconditions (from issue 03 completion):**
- `BaseSchemaProcessor<Init, Unknown>::from_discovery()` and `run()` exist.
- `BaseSchemaResolution` with `Fresh`/`New` exists.
- `Construction<Fresh>::fetch()` exists (dead-coded).
- `save_base_schema`, `find_base_schema_by_id`, `save_raw_schema_view`, `find_schema_id_by_path` all available on `Repository`.
- `ExcludesDelta`, `ExtendsDelta`, `PropertyDelta`, `PropertyDeltaEngine` all implemented and tested in `delta.rs`.
- `SchemaVersion::new`, `SchemaVersion::excludes()`, `SchemaVersion::extends()`, `SchemaVersion::bank_references()` available on `SchemaVersion`.
- `RawSchemaView::try_from_raw_with_hashes`, `RawSchemaView::update_content_hash`, `RawSchemaView::current()` available.
