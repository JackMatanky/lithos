## Implementation Notes (2026-05-13)

- Runtime schema orchestration surfaces were moved to segregated read/write
  seams instead of directly binding to legacy `schema::storage::Repository`:
  - `Builder` now requires only `SchemaReadRepository` +
    `SchemaWriteRepository` seams.
  - `SchemaProcessor` refresh/construction/completion write paths now bind to
    `SchemaWriteRepository`, and construction reads bind to
    `SchemaReadRepository`.
  - `PropertyBankProcessor` repository bounds were migrated to
    `SchemaReadRepository` / `SchemaWriteRepository`.
- Discovery compatibility seam was fully removed:
  - deleted `DiscoveryReadRepository` trait from `schema/repository.rs`
  - removed `DiscoveryReadRepository` impls from
    `schema/storage_v2/read.rs` and `schema/storage_v2/testing.rs`
  - discovery now performs local path+vector zips to build keyed maps where
    needed (`Vec<Option<T>>` -> `HashMap<RelativePath, T>` conversion in
    `schema/discovery.rs`).
- Added a compile-time test guard in `builder` tests to ensure `Builder::new`
  accepts the segregated seam trait set.
- Transitional blanket compatibility bridges in `schema/repository.rs` were
  removed after runtime cutover, and explicit seam impls were added for test
  infrastructure (`InMemoryRepository`) in
  `schema/storage_v2/testing.rs`.
- Canonical v2 adapter naming was cleaned up by renaming
  `SchemaRedbRepository` to `RedbRepository` across `storage_v2` and
  integration tests.
