## What to build

Establish a shared DB testing seam that standardizes in-memory testing
infrastructure across contexts while keeping context Repository Adapters local.

This slice is complete when Schema, Note, Template, and Config migrations can
rely on the same testing primitives and error semantics for in-memory adapters.

## Agent Brief (v2 - 2026-05-21)

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Add `db::testing` module with shared testing infrastructure
primitives for context-local in-memory Repository Adapters

**Current behavior:**
Testing adapters across contexts (Schema, Config, Template, Note) use
inconsistent patterns for lock handling (`RwLock` poison mapping), error
conversion, and test instrumentation. Schema has
`InMemoryError::LockPoisoned`; Config maps lock poison to `ValidationFailed`.
There is no shared failure injection or operation counting infrastructure.
This inconsistency increases maintenance burden and risks semantic drift in
test behavior.

**Desired behavior:**
1. A new `db::testing` module provides **infra-only primitives** (no domain
   semantics):
   - Temporary `Store` creation helpers
   - Generic lock acquisition helpers with consistent poison handling
   - Operation counters for read/write/batch instrumentation
   - Deterministic failure injection framework
   - Shared `InMemoryDbError` type for testing failures
   - Contract test scaffolding for atomicity/index/idempotency checks

2. Contexts (Schema/Note/Template/Config) maintain **local in-memory
   Repository Adapters** that:
   - Own their projection semantics and domain invariants
   - Consume `db::testing` primitives for infrastructure concerns
   - Map `InMemoryDbError` → context errors via `From<InMemoryDbError>`

**Architecture constraints:**
- **DB owns**: Infrastructure primitives (store setup, lock helpers, counters,
  injectors, error type)
- **Contexts own**: Domain projection logic, entity-specific indices, business
  invariants
- **Explicit non-goals**: No generic `db::InMemoryRepository` (would violate
  DB's "Not Owned Here" boundary)

### Explicit `db::testing` design (required for this issue)

Create a new test-only module:

- `lithos-core/src/db/testing.rs`

Compilation target:

- Prefer `#[cfg(any(test, feature = "bench"))]` if bench targets need it.
- Otherwise `#[cfg(test)]` is acceptable.

This module must expose **infra primitives only**. It must not contain context
repository behavior or domain projection semantics.

#### 1) Test store creation

- **Trait:** `TestStoreFactory`
  - `open_temp_store() -> Result<(tempfile::TempDir, Store), DbError>`
  - `open_temp_store_arc() -> Result<(tempfile::TempDir, Arc<Store>), DbError>`
- **Optional convenience struct:** `TestStore`
  - `pub fn open_temp() -> Result<(tempfile::TempDir, Store), DbError>`
  - `pub fn open_temp_arc() -> Result<(tempfile::TempDir, Arc<Store>), DbError>`
- **Purpose:** Standardized temporary `Store` setup across
  Schema/Note/Template/Config tests.

#### 2) Lock handling helpers

- **Helper functions (generic):**
  - `read_lock<T>(lock: &RwLock<T>, ctx: &'static str) -> Result<RwLockReadGuard<'_, T>, InMemoryDbError>`
  - `write_lock<T>(lock: &RwLock<T>, ctx: &'static str) -> Result<RwLockWriteGuard<'_, T>, InMemoryDbError>`
  - `mutex_lock<T>(lock: &Mutex<T>, ctx: &'static str) -> Result<MutexGuard<'_, T>, InMemoryDbError>`
- **Purpose:** Unify lock-poison error mapping so all in-memory adapters expose
  consistent failure semantics.

#### 3) Operation instrumentation

- **Struct:** `OpCounters`
  - Backed by `AtomicUsize` fields (for example: reads, writes, batches,
    deletes, injected_failures)
  - Methods: `inc_read`, `inc_write`, `inc_batch`, `snapshot`
- **Snapshot struct:** `OpCountersSnapshot`
  - Plain values for assertions.
- **Purpose:** Replace ad-hoc call counters in context tests with a shared,
  stable instrumentation seam.

#### 4) Deterministic failure injection

- **Enum:** `FailurePoint`
  - At minimum include: `BeforeRead`, `BeforeWrite`, `AfterSerialize`,
    `BeforeCommit`
  - Can be extended conservatively if tests require more precision.
- **Trait:** `FailureInjector`
  - `fail_at(point: FailurePoint) -> Result<(), InMemoryDbError>`
- **Struct:** `InMemoryHarness`
  - Holds optional injector + counters
  - Context adapters embed this harness in their state for shared behavior
- **Purpose:** Deterministic rollback/atomicity/failure-path testing across
  all context in-memory adapters.

#### 5) Shared test-infra error type

- **Enum:** `InMemoryDbError` (in `db::testing`, not production `db/error.rs`
  unless explicitly promoted later)
- Required variants:
  - `LockPoisoned { context: &'static str }`
  - `InjectedFailure { point: FailurePoint, reason: Box<str> }`
  - `InvariantViolation { message: Box<str> }`
- Context adapters map this error via `From<InMemoryDbError>` into their own
  context error surface (Schema/Config/Template/Note).

#### 6) Contract test harness utilities (infra-only)

Add a small shared test utility for context adapters to run common behavioral
contracts without introducing shared domain logic.

- Contract capabilities:
  - batch atomicity checks
  - index consistency after save/delete
  - idempotent delete checks
- Contexts provide closures/fixtures/entities; `db::testing` provides the
  orchestration scaffolding only.

### Explicit non-goals

- Do **not** add a generic `db::InMemoryRepository` domain adapter.
- Do **not** add shared domain index maps in `db`.
- Do **not** move context-specific invariants from Schema/Note/Template/Config
  into DB.

These non-goals protect DB context locality per `db/CONTEXT.md` and avoid
creating a shallow cross-context fake storage module.

**Key interfaces:**
- `db::testing` module
- `InMemoryDbError`
- Context-local in-memory Repository Adapters
- `TestStoreFactory`, `FailureInjector`, `InMemoryHarness`, `OpCounters`
- `FailurePoint`

**Acceptance criteria:**
- [ ] `lithos-core/src/db/testing.rs` exists and compiles under
      `#[cfg(any(test, feature = "bench"))]`
- [ ] `TestStoreFactory` or `TestStore` is implemented with `open_temp()` and
      `open_temp_arc()` methods
- [ ] Generic lock helpers (`read_lock`, `write_lock`, `mutex_lock`) are
      implemented and return `InMemoryDbError` on poison
- [ ] `OpCounters` struct is implemented with atomic fields and `inc_*` +
      `snapshot()` methods
- [ ] `FailurePoint` enum, `FailureInjector` trait, and `InMemoryHarness`
      struct are implemented
- [ ] `InMemoryDbError` enum is defined with `LockPoisoned`,
      `InjectedFailure`, `InvariantViolation` variants
- [ ] At least one context (recommend Schema) demonstrates usage by:
  - Converting existing lock acquisition to use `db::testing::read_lock` /
    `write_lock`
  - Implementing `From<InMemoryDbError>` for its error type
  - Writing at least one test that uses `OpCounters` or `FailureInjector`
- [ ] Contract test scaffolding exists (even if minimal stub for now)
- [ ] All tests pass (`mise run test`)
- [ ] No clippy warnings (`mise run lint`)
- [ ] Documentation exists in module-level doc comment explaining "infra-only"
      boundary and non-goals

**Out of scope:**
- Implementing Note/Template/Config migrations (those are issues 07/08/09)
- Refactoring all existing Schema/Config tests to use new primitives
  (demonstration in one context is sufficient)
- Finalizing serialization placement policy (deferred to issue 11)
- Adding any domain-specific logic to `db::testing` (contexts own their
  projection semantics)

### Naming Convention

- **Module names**: Canonical names from unit-naming.md (`locking`, `counters`, `contracts`)
- **Test functions**: Verb-first formula: `[action]_[expected]_[condition]`
- **Examples**: `returns_guard_when_not_poisoned`, `increments_read_count`, `verifies_idempotent_delete`

### Red-Green-Refactor Sequence

Follow vertical slicing: one test → one implementation → repeat.

#### Phase 1: Lock Helpers (5 tests)

**Module**: `locking` (canonical name for lock/concurrency behavior)

1. **`returns_read_guard_when_not_poisoned`**
   - Arrange: `RwLock::new(42)`
   - Act: `read_lock(&data, "test")`
   - Assert: `unwrap()` succeeds, `*guard == 42`

2. **`returns_error_when_read_lock_poisoned`**
   - Arrange: poisoned RwLock (panic in write guard)
   - Act: `read_lock(&data, "test")`
   - Assert: `Err(InMemoryDbError::LockPoisoned { .. })`

3. **`returns_write_guard_when_not_poisoned`**
   - Arrange: `RwLock::new(42)`
   - Act: `write_lock(&data, "test")`
   - Assert: `unwrap()` succeeds, can mutate `*guard = 100`

4. **`returns_mutex_guard_when_not_poisoned`**
   - Arrange: `Mutex::new(42)`
   - Act: `mutex_lock(&data, "test")`
   - Assert: `unwrap()` succeeds, `*guard == 42`

5. **`allows_concurrent_read_locks`**
   - Arrange: `Arc<RwLock<_>>`
   - Act: acquire 2 read guards simultaneously
   - Assert: both succeed, see same data (verifies RwLock semantics)

**Refactor checkpoint**: Extract `poison_lock` test helper to `fixtures` module

#### Phase 2: Operation Counters (5 tests)

**Module**: `counters` (operation instrumentation behavior)

6. **`starts_with_zero`**
   - Arrange: `OpCounters::default()`
   - Act: `snapshot()`
   - Assert: all fields == 0

7. **`increments_read_count`**
   - Arrange: default counters
   - Act: `inc_read()` twice
   - Assert: `snapshot().reads == 2`

8. **`increments_write_and_batch_counts`**
   - Arrange: default counters
   - Act: `inc_write()`, `inc_batch()`
   - Assert: `writes == 1, batches == 1`

9. **`increments_concurrently_from_multiple_threads`**
   - Arrange: `Arc<OpCounters>`, 10 threads
   - Act: each thread calls `inc_read()` 100 times
   - Assert: `reads == 1000` (verifies atomicity)

10. **`resets_all_counters_to_zero`**
    - Arrange: counters with incremented values
    - Act: `reset()`
    - Assert: all fields == 0 (critical for test isolation)

**Implementation**: Add `OpCounters::reset()` method

#### Phase 3: Failure Injection (3 tests)

**Module**: `failure_injection`

11. **`succeeds_when_no_injector_configured`**
    - Arrange: `InMemoryHarness::new()` (no injector)
    - Act: `fail_at(FailurePoint::BeforeWrite)`
    - Assert: `Ok(())`

12. **`injects_failure_when_injector_configured`**
    - Arrange: harness with `AlwaysFailInjector`
    - Act: `fail_at(FailurePoint::BeforeWrite)`
    - Assert: `Err(InMemoryDbError::InjectedFailure { .. })`

13. **`injects_selectively_by_failure_point`**
    - Arrange: harness with `SelectiveInjector { fail_on_write: true }`
    - Act: call `fail_at` for both `BeforeRead` and `BeforeWrite`
    - Assert: read succeeds, write fails (granular control)

**Refactor checkpoint**: Add `AlwaysFailInjector` and `SelectiveInjector` to `fixtures`

#### Phase 4: Store Constructors (2 tests)

**Module**: `constructors` (canonical name for creation/construction behavior)

14. **`creates_temp_store`**
    - Act: `TestStore::open_temp()`
    - Assert: store is usable (`store.read().unwrap()` succeeds)

15. **`creates_stores_with_unique_paths`**
    - Arrange: create 2 stores
    - Assert: `path1 != path2` (verifies test isolation)

#### Phase 5: Schema Integration (2 tests)

**Location**: `lithos-core/src/schema/storage/testing.rs`
**Module**: `integration` (demonstrates db::testing usage in context)

16. **`converts_all_error_variants`**

      - `LockPoisoned` → `InMemoryError::LockPoisoned`
      - `InjectedFailure` → `InMemoryError::Internal`
      - `InvariantViolation` → `InMemoryError::Internal`

17. **`maintains_lock_semantics_after_migration`**
    - Arrange: InMemoryRepository using db::testing lock helpers
    - Act: save + find operations
    - Assert: counters reflect expected lock acquisitions (regression guard)

**Implementation**: Add `From<InMemoryDbError>` impl in `schema/storage/testing.rs`

#### Phase 6: Repository Contract Tests (2 tests)

## Test Value Rationale

### Included Tests (19 total)

**In `db/testing.rs` (15 tests)**:
- Lock acquisition happy paths (read/write/mutex)
- Error handling (poison detection)
- Counter instrumentation (increment, snapshot, reset)
- Failure injection framework (no-op, always-fail, selective)
- Store constructors (basic + isolation via unique paths)
- Thread safety proofs (concurrent reads, atomic increments)

**In `schema/storage/testing.rs` (4 tests)**:
- Error conversion (`From<InMemoryDbError>`)
- Lock semantics preservation (regression guard)
- Repository correctness contracts (idempotency, index consistency)

### Excluded Tests (18 removed)

**Stdlib behavior tests** (not our code):
- RwLock write blocking behavior
- Arc strong_count semantics
- Counter overflow wrapping
- TempDir cleanup on drop

**Advanced features** (not needed for MVP):
- Probabilistic failure injection
- Dynamic injector replacement
- Mixed concurrent operation stress tests

**Implementation details** (low diagnostic value):
- Context string preservation in errors
- Error message wording verification

**Integration test territory** (cross-boundary behavior):
- Batch atomicity with injected failures
- Complex multi-index consistency scenarios
