## What to build

Implement the construction side of the redesigned `DiscoveryService`: stable configuration, self-builder setters, and `build()` validation.

This slice should not execute discovery. It establishes the stable service configuration that will later be combined with `DiscoveryContext` by the typestate processor.

## Acceptance criteria

- [ ] `discovery/service.rs` defines `DiscoveryService` as the public discovery service facade inside the crate.
- [ ] `DiscoveryService` uses the self-builder pattern: `DiscoveryService::default().setter(...).build()?`.
- [ ] `DiscoveryService::build()` returns `Result<Self, DiscoveryError>` and validates builder invariants.
- [ ] Stable service config includes root marker path patterns and global marker path patterns.
- [ ] Stable service config includes project boundary marker patterns such as `.git` and `.workspace`.
- [ ] Stable service config includes global namespace directories or a stable representation from which global candidate directories can be derived.
- [ ] Stable service config includes traversal policy such as `allow_marker_at_ceiling`.
- [ ] `suppress_global` is not part of stable service config; it remains per-invocation state on `DiscoveryFlags` from issue 10.
- [ ] Marker pattern constants are named as patterns, not files: `ROOT_MARKER_PATTERNS`, `GLOBAL_MARKER_PATTERNS`, or equivalent.
- [ ] `DiscoveryService` does not acquire CWD, read environment variables, parse CLI flags, run traversal, probe files, or call Config.
- [ ] `DiscoveryService` does not expose a second trusted-path discovery method in this slice.
- [ ] Tests cover default construction, each setter, `build()` success, `build()` validation failures, and the fact that `suppress_global` is absent from service config.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement

**Summary:** Implement `DiscoveryService::build()` and stable Discovery service configuration without running discovery.

**Current behavior:**
Discovery contracts and Bootstrapper context acquisition exist, but there is no constructed service facade that owns stable discovery policy and target definitions.

**Desired behavior:**
`DiscoveryService` can be configured with stable discovery policy and validated with `build()`. It is ready for the later typestate processor issue to call, but it does not execute any phase itself in this slice.

**Key interfaces:**
- `DiscoveryService` — self-builder facade and stable configuration owner.
- `DiscoveryService::build()` — validates stable configuration and returns the built service.
- Root/global marker pattern constants — target definitions for later probing.
- Boundary marker patterns — project boundary definitions for later traversal.

**Acceptance criteria:**
- [ ] `DiscoveryService::build()` is implemented and tested.
- [ ] Stable service config is separate from per-invocation `DiscoveryContext`.
- [ ] `suppress_global` remains on `DiscoveryFlags`.
- [ ] No discovery phase execution is implemented here.

**Out of scope:**
- Typestate processor implementation.
- Preemption, probing, traversal, global search, finalization, or candidate ordering.
- Bootstrapper running Discovery.
- Config integration.
