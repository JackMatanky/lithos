## What to build

Add `CacheRoot` to `DiscoveryResult` so that the resolved cache directory — and the provenance of how it was chosen — is produced by the discovery pipeline itself rather than being assembled later from a static config field.

The current `CacheConfig::cache_dir()` returns a `CacheDir` wrapping a `RelativeDirPath`; it is a declarative config value only. Callers must combine it with a vault root at call time, and there is no env-var override or platform fallback. This issue deprecates that field and introduces proper discovery of the cache root as part of the `DiscoveryProcessor` pipeline.

## Data model

Place all new types in `lithos-core/src/discovery/location.rs`.

> **Implementation note:** The plan showed `pub location` and `pub path` fields.
> The implementation made both fields private to comply with the project standard
> (private fields, validated constructors). A `CacheRoot::new(location, path)`
> constructor and `location() -> &CacheLocation` / `path() -> &Path` accessors
> were added instead.

```rust
/// The resolved cache root with its provenance.
///
/// `path` is a directory path (not a file) and is not validated for existence
/// at construction — callers are responsible for creating it when needed.
pub struct CacheRoot {
    // fields are private; use CacheRoot::new(), .location(), .path()
    location: CacheLocation,
    path: PathBuf,
}

/// Top-level branch: is the cache local to the vault or at a global/platform level?
pub enum CacheLocation {
    Local(LocalCacheLocation),
    Global(GlobalCacheLocation),
}

/// Local (vault-scoped) cache location variants.
pub enum LocalCacheLocation {
    /// `<vault_root>/.lithos/cache/`
    ///
    /// Selected when a vault root is available and no env override is set.
    ProjectCacheDirectory,
}

/// Global (user/platform) cache location variants.
pub enum GlobalCacheLocation {
    /// Sourced from the `LITHOS_CACHE_DIR` environment variable.
    ///
    /// Used when the env var is set and non-empty, regardless of whether a
    /// vault root was found.
    EnvironmentOverride,
    /// Resolved from the OS platform user-cache convention:
    /// - Linux:   `$XDG_CACHE_HOME/lithos/` or `~/.cache/lithos/`
    /// - macOS:   `~/Library/Caches/lithos/`
    /// - Windows: `%LOCALAPPDATA%\lithos\Cache\`
    ///
    /// Used as a fallback when no vault root is available and no env var is set.
    PlatformUserCache,
}
```

## Resolution precedence (highest → lowest)

1. **`LITHOS_CACHE_DIR` env var** — if set and non-empty, resolves as an absolute
   path. Emits `GlobalCacheLocation::EnvironmentOverride`. Applies regardless of
   whether a vault root was found.
2. **Local project default** — if a vault root is available (i.e. the winning vault
   `CandidatePath::base()` is known), resolves to `<vault_root>/.lithos/cache/`.
   Emits `LocalCacheLocation::ProjectCacheDirectory`.
3. **Platform user cache (fallback)** — used when no vault root is available and no
   env var is set. Emits `GlobalCacheLocation::PlatformUserCache`.

`CacheConfig::cache_dir` is **deprecated** by this issue. The static relative-path
field is no longer consulted during cache root resolution. Removing it from the
config schema is in scope here.

The resolved `path` is a directory path and is **not** checked for existence at
construction. Callers (e.g. the DB layer) are responsible for creating it.

## Implementation constraints

### Carrying `LITHOS_CACHE_DIR` through the pipeline

`DiscoveryEnv` is a closed data-holding struct — it does not call `std::env::var`
internally. The Bootstrapper reads env vars before constructing `DiscoveryContext`
and injects them as typed values. `LITHOS_CACHE_DIR` is not yet a field on
`DiscoveryEnv`.

To make `LITHOS_CACHE_DIR` available inside the processor pipeline, this issue must:

1. Add `cache_dir: Option<PathBuf>` to `DiscoveryEnv` (an unvalidated `PathBuf`,
   not `DirPath` — the directory need not exist yet at context-construction time).
2. Add a corresponding `cache_dir()` getter and update `DiscoveryEnv::new()`.
3. Have the Bootstrapper read `LITHOS_CACHE_DIR` from `std::env::var` and pass the
   raw path into `DiscoveryEnv` — following the same pattern as the existing
   `vault_dir` and `config_file` fields.
4. The new `CacheResolution` phase reads `self.ctx.env().cache_dir()` to obtain the
   override value (see Pipeline change below).

`ctx` is already accessible at every phase — the `DiscoveryProcessor` carries
`ctx: &'ctx DiscoveryContext<'ctx>` through every phase transition unchanged.

### Pipeline change: `CacheResolution` phase

Cache root computation belongs in a dedicated pipeline phase, not inside `finalize()`.
The `finalize()` method's sole responsibility is packing accumulated state into
`DiscoveryResult`; adding resolution logic there would mix concerns and break the
established pattern where every computation happens in a `From` transition.

A new `CacheResolution` phase is inserted immediately before `Finalized`. Every
path that previously transitioned directly to `Finalized` now transitions through
`CacheResolution` first:

```
FlagOverride (VaultAndConfigSet)        ──┐
EnvOverride  (VaultProbedSkipGlobal)    ──┤
AscendingTraversal (AscendSkipGlobal)   ──┼──► CacheResolution ──► Finalized
GlobalResolution                        ──┘
```

The `CacheResolution` transition has access to the fully-accumulated `vault`
candidates and `self.ctx.env().cache_dir()`. It computes the `CacheRoot` and stores
it in a new `cache_root` field on `DiscoveryProcessor`. `finalize()` then packs
`vault`, `global`, and `cache_root` into `DiscoveryResult` without performing any
additional computation.

The `DiscoveryProcessor` struct gains:
- A `cache_root: Option<CacheRoot>` field initialised to `None`.
- Populated to `Some(...)` exclusively during the `CacheResolution` transition.

`DiscoveryService::discover()` in `service.rs` is updated to add the extra hop on
all five terminal paths.

### `DirPath` construction

`DirPath::try_new(PathBuf)` is **fallible and filesystem-live** — it calls
`path.is_dir()` at construction, so the directory must already exist on disk.

`CacheRoot::path` must therefore **not** be a `DirPath`. Use `PathBuf` instead
(or a newtype wrapper that does not enforce existence). The resolved cache path
is not validated for existence at construction — creation is the caller's
responsibility.

```rust
pub struct CacheRoot {
    pub location: CacheLocation,
    pub path: PathBuf,   // not DirPath; directory need not exist yet
}
```

### `dirs` crate

`dirs` is **not** currently a dependency of `lithos-core`. The current published
version is **6** (`dirs = "6"`). It must be added to both:

- `Cargo.toml` `[workspace.dependencies]` as `dirs = "6"`
- `lithos-core/Cargo.toml` `[dependencies]` as `dirs.workspace = true`

`dirs::cache_dir()` is used for `PlatformUserCache` resolution.

### `DiscoveryEnv::new()` is a breaking constructor change

Adding `cache_dir: Option<PathBuf>` as a 4th positional parameter breaks every
existing call site. Unlike `vault_dir` and `config_file`, `cache_dir` is
**not validated** — it is stored as-is without filesystem checks, and no new
`EnvironmentOverrideError` variant is needed. All existing call sites pass `None`
as the new argument; the Bootstrapper passes the value read from `LITHOS_CACHE_DIR`.

### `DiscoveryResult::new()` is a breaking constructor change

Adding `cache_root: CacheRoot` as a 3rd required parameter breaks every existing
call site in `service.rs` tests (~4 sites) and `bootstrap.rs` tests (~12 mock
setups). All must be updated to supply a `CacheRoot` value.

## Vault root derivation

`DiscoveryResult` does not expose a `vault_root` field directly. The vault root is
derived from the `base()` of the winning vault `CandidatePath`:

```rust
let vault_root: Option<&DirPath> = self.vault.first().map(|c| c.base());
```

This derivation happens inside the `CacheResolution` transition (on the processor,
before the result is constructed).

## Integration points

- `CacheRoot` is added as a field on `DiscoveryResult`:
  ```rust
  pub struct DiscoveryResult {
      vault: Box<[CandidatePath]>,
      global: Box<[CandidatePath]>,
      cache_root: CacheRoot,   // new
  }
  ```
- The new `CacheResolution` phase on `DiscoveryProcessor` computes the `CacheRoot`
  and stores it before `Finalized` is entered.
- `finalize()` packs `vault`, `global`, and `cache_root` into `DiscoveryResult`
  without additional logic.
- `Bootstrapper` does not need changes — it already threads `DiscoveryResult`
  through to `BootstrapResult` consumers.
- `CacheConfig::cache_dir` is deprecated; any existing callers of `CacheConfig::cache_dir()`
  must be migrated to use `DiscoveryResult::cache_root()`.

**Category:** enhancement

**Summary:** Add `CacheRoot` to `DiscoveryResult` via a new `CacheResolution` typestate

### Slice 3 — `DiscoveryProcessor`: `CacheResolution` phase

**Files:** `lithos-core/src/discovery/processor.rs`

**Structural changes:**
1. Add `pub(crate) struct CacheResolution;` phase marker.
2. Add `cache_root: Option<CacheRoot>` field to `DiscoveryProcessor` (initialised
   to `None` in `Init::new`).
3. Add a single generic `From<DiscoveryProcessor<'ctx, P>> for DiscoveryProcessor<'ctx, CacheResolution>`
   impl that computes `CacheRoot` from accumulated state and stores it in `cache_root`.

**The resolution function** (private, in `processor.rs`):
```rust
fn resolve_cache_root(
    env_cache_dir: Option<&PathBuf>,
    vault_root: Option<&DirPath>,
) -> CacheRoot {
    if let Some(path) = env_cache_dir {
        return CacheRoot {
            location: CacheLocation::Global(GlobalCacheLocation::EnvironmentOverride),
            path: path.clone(),
        };
    }
    if let Some(root) = vault_root {
        return CacheRoot {
            location: CacheLocation::Local(LocalCacheLocation::ProjectCacheDirectory),
            path: root.as_path().join(".lithos/cache"),
        };
    }
    let path = dirs::cache_dir()
        .map(|p| p.join("lithos"))
        .unwrap_or_else(|| PathBuf::from(".lithos/cache"));
    CacheRoot {
        location: CacheLocation::Global(GlobalCacheLocation::PlatformUserCache),
        path,
    }
}
```

Note: `dirs::cache_dir()` returns `Option<PathBuf>`. The
`.unwrap_or_else(|| PathBuf::from(".lithos/cache"))` fallback covers the
pathological case where the OS provides no cache dir (required to avoid `unwrap()`
in production code per lint rules).

**New behaviors to verify** (new `mod cache_resolution` in `processor.rs::tests`):

| Test name | Behavior |
|---|---|
| `returns_environment_override_when_cache_dir_env_is_set` | env set → `EnvironmentOverride`, path matches env value |
| `returns_environment_override_regardless_of_vault_presence` | env set + vault found → env still wins |
| `returns_project_cache_directory_when_vault_present_and_no_env` | no env, vault found → `ProjectCacheDirectory`, path is `<vault>/.lithos/cache` |
| `returns_platform_user_cache_when_no_vault_and_no_env` | no env, no vault → `PlatformUserCache` |
| `path_is_not_validated_for_existence_at_construction` | `CacheRoot` path need not exist on disk |

### Deviations from the TDD plan

**1. `CacheRoot` fields are private (project standard)**

The plan showed `pub location` and `pub path`. During review this was flagged as a
violation of the project's "private fields, validated constructors" standard. The
implementation uses private fields with:

- `CacheRoot::new(location: CacheLocation, path: PathBuf) -> Self`
- `CacheRoot::location() -> &CacheLocation`
- `CacheRoot::path() -> &Path` (returns `&Path`, not `&PathBuf`, for ergonomics)

**2. `cache_dir()` returns `Option<&Path>`, not `Option<&PathBuf>`**

The idiomatic Rust return type for a getter over `Option<PathBuf>` is `Option<&Path>`
(via `as_deref()`). The field type remains `Option<PathBuf>` internally.

**3. Generic `From<P>` replaced by concrete impls + shared helper**

The plan specified a single generic `From<DiscoveryProcessor<'ctx, P>> for
DiscoveryProcessor<'ctx, CacheResolution>`. This is blocked by Rust's blanket impl
conflict with `From<T> for T`. The implementation uses five concrete `From` impls
(`FlagOverride`, `EnvOverride`, `AscendingTraversal`, `GlobalResolution`, and a
test-only `Init`) each delegating to a private `run_cache_resolution()` helper
(named after `run_global_resolution` for consistency).

**4. `From<Init> for CacheResolution` is test-only**

The `From<Init>` impl used only in tests was gated with `#[cfg(test)]` to prevent
accidental production use. In production the pipeline always goes `Init → FlagOverride`
first; jumping directly to `CacheResolution` would compute `CacheRoot` before any
vault probing, silently falling through to `PlatformUserCache` even when a vault is
present.

**5. `build_context` takes an explicit `cache_dir` parameter**

The plan placed the `env::var_os("LITHOS_CACHE_DIR")` read inside `build_context`.
During review this was identified as making `build_context` impure and untestable
without env mutation. The read was moved to `run()` and `run_discovery_only()`.
`build_context` now takes `cache_dir: Option<PathBuf>` as a 4th explicit parameter,
making it fully pure and testable.

**6. Shared `placeholder_cache_root()` fixture**

The plan specified one helper per file. The implementation consolidates into a single
`pub(crate) fn placeholder_cache_root()` inside `location::tests`, which the helpers
in `service.rs`, `bootstrap.rs`, `port.rs`, and `builder.rs` delegate to.

**7. `into_cache_resolution` renamed to `run_cache_resolution`**

The `into_` prefix implied `Into` trait semantics. Renamed to `run_cache_resolution`
to match `run_global_resolution`.

**8. `mod.rs` module doc updated**

The module-level doc still described the old architecture (`DiscoveryEngine`,
`DiscoveryPolicy`, `DiscoveryInput`). Updated to reflect the current API including
the new `location` module.

**9. `deny.toml` updated**

`MPL-2.0` added to the allowed licence list (required by `option-ext`, a transitive
dep of `dirs 6.x` via `dirs-sys`). A `getrandom 0.2.17` ban-skip was added for the
version pulled by `dirs-sys → redox_users` (conflicts with the 0.4.x pulled by
`uuid`/`tempfile`/`rkyv`).

## Open items

### AC-14: caller migration deferred

**Criterion:** All callers of `CacheConfig::cache_dir()` are migrated to
`DiscoveryResult::cache_root()`.

**Status:** Not met. Callers were deprecated and suppressed with
`#[expect(deprecated, reason = "...")]`. No call site was replaced with
`DiscoveryResult::cache_root()`.

**Why:** `CacheConfig::cache_dir()` returns a relative `CacheDir` (a `RelativeDirPath`
wrapping a vault-relative string like `.cache`). `DiscoveryResult::cache_root()`
returns an absolute `CacheRoot` (a resolved `PathBuf`). These are semantically
distinct and cannot be mechanically substituted. Completing the migration requires
either:

1. Threading `DiscoveryResult` through to `Config::to_cache_spec()` and its callers, or
2. Removing `to_cache_spec()` and its callers once downstream consumers adopt
   `DiscoveryResult::cache_root()` directly.

**Remaining call sites** (all suppressed with `#[expect(deprecated)]`):

| File | Call | Context |
|---|---|---|
| `config/aggregate.rs:306` | `self.cache.cache_dir()` inside `to_cache_spec()` | `to_cache_spec` is itself deprecated |
| `config/aggregate.rs:650,750,912,959` | `config.cache().cache_dir()` | tests of deprecated accessor |
| `config/vault.rs:885` | `vault.cache()...cache_dir()` | test of deprecated accessor |
| `config/cache.rs:298,314` | `config.cache_dir()` | tests of deprecated accessor |

**Suggested follow-on:** Create a new issue to remove `CacheConfig::cache_dir()`,
`CacheConfig` (if no other callers remain), and `Config::to_cache_spec()` once
downstream consumers (e.g. the DB/indexer layer) are updated to read
`DiscoveryResult::cache_root()` from the bootstrapper result.
