## What to build

Add `CacheRoot` to `DiscoveryResult` so that the resolved cache directory — and the provenance of how it was chosen — is produced by the discovery pipeline itself rather than being assembled later from a static config field.

The current `CacheConfig::cache_dir()` returns a `CacheDir` wrapping a `RelativeDirPath`; it is a declarative config value only. Callers must combine it with a vault root at call time, and there is no env-var override or platform fallback. This issue deprecates that field and introduces proper discovery of the cache root as part of the `DiscoveryProcessor` pipeline.

## Data model

Place all new types in `lithos-core/src/discovery/location.rs`.

```rust
/// The resolved cache root with its provenance.
///
/// `path` is a directory path (not a file) and is not validated for existence
/// at construction — callers are responsible for creating it when needed.
pub struct CacheRoot {
    /// The strategy that produced this cache root.
    pub location: CacheLocation,
    /// The resolved absolute directory path.
    /// Example: `<vault_root>/.lithos/cache/`
    ///
    /// Not validated for existence at construction — callers are responsible
    /// for creating the directory when needed.
    pub path: PathBuf,
}

/// Top-level branch: is the cache local to the vault or at a global/platform level?
pub enum CacheLocation {
    Local(LocalCacheLocation),
    Global(GlobalCacheLocation),
}

/// Local (vault-scoped) cache location variants.
pub enum LocalCacheLocation {
    /// `<vault_root>/.lithos/cache/`
    ///
    /// Selected when a vault root is available and no env override is set.
    ProjectCacheDirectory,
}

/// Global (user/platform) cache location variants.
pub enum GlobalCacheLocation {
    /// Sourced from the `LITHOS_CACHE_DIR` environment variable.
    ///
    /// Used when the env var is set and non-empty, regardless of whether a
    /// vault root was found.
    EnvironmentOverride,
    /// Resolved from the OS platform user-cache convention:
    /// - Linux:   `$XDG_CACHE_HOME/lithos/` or `~/.cache/lithos/`
    /// - macOS:   `~/Library/Caches/lithos/`
    /// - Windows: `%LOCALAPPDATA%\lithos\Cache\`
    ///
    /// Used as a fallback when no vault root is available and no env var is set.
    PlatformUserCache,
}
```

## Resolution precedence (highest → lowest)

1. **`LITHOS_CACHE_DIR` env var** — if set and non-empty, resolves as an absolute
   path. Emits `GlobalCacheLocation::EnvironmentOverride`. Applies regardless of
   whether a vault root was found.
2. **Local project default** — if a vault root is available (i.e. the winning vault
   `CandidatePath::base()` is known), resolves to `<vault_root>/.lithos/cache/`.
   Emits `LocalCacheLocation::ProjectCacheDirectory`.
3. **Platform user cache (fallback)** — used when no vault root is available and no
   env var is set. Emits `GlobalCacheLocation::PlatformUserCache`.

`CacheConfig::cache_dir` is **deprecated** by this issue. The static relative-path
field is no longer consulted during cache root resolution. Removing it from the
config schema is in scope here.

The resolved `path` is a directory path and is **not** checked for existence at
construction. Callers (e.g. the DB layer) are responsible for creating it.

## Implementation constraints

### Carrying `LITHOS_CACHE_DIR` through the pipeline

`DiscoveryEnv` is a closed data-holding struct — it does not call `std::env::var`
internally. The Bootstrapper reads env vars before constructing `DiscoveryContext`
and injects them as typed values. `LITHOS_CACHE_DIR` is not yet a field on
`DiscoveryEnv`.

To make `LITHOS_CACHE_DIR` available inside `finalize()`, this issue must:

1. Add `cache_dir: Option<PathBuf>` to `DiscoveryEnv` (an unvalidated `PathBuf`,
   not `DirPath` — the directory need not exist yet at context-construction time).
2. Add a corresponding `cache_dir()` getter and update `DiscoveryEnv::new()`.
3. Have the Bootstrapper read `LITHOS_CACHE_DIR` from `std::env::var` and pass the
   raw path into `DiscoveryEnv` — following the same pattern as the existing
   `vault_dir` and `config_file` fields.
4. `finalize()` reads `self.ctx.env().cache_dir()` to obtain the override value.

`ctx` is already accessible inside `finalize()` — the `DiscoveryProcessor` carries
`ctx: &'ctx DiscoveryContext<'ctx>` through every phase transition unchanged.

### `DirPath` construction

`DirPath::try_new(PathBuf)` is **fallible and filesystem-live** — it calls
`path.is_dir()` at construction, so the directory must already exist on disk.

`CacheRoot::path` must therefore **not** be a `DirPath`. Use `PathBuf` instead
(or a newtype wrapper that does not enforce existence). The resolved cache path
is not validated for existence at construction — creation is the caller's
responsibility.

Update the data model accordingly:

```rust
pub struct CacheRoot {
    pub location: CacheLocation,
    pub path: PathBuf,   // not DirPath; directory need not exist yet
}
```

### `dirs` crate

`dirs` is **not** currently a dependency of `lithos-core`. It must be added to
`lithos-core/Cargo.toml` (and the workspace `Cargo.toml` `[workspace.dependencies]`
if the project uses centralised dependency management) before `PlatformUserCache`
resolution can be implemented. Add `dirs = "5"` (or the current semver-compatible
version).

## Vault root derivation

`DiscoveryResult` does not expose a `vault_root` field directly. The vault root is
derived from the `base()` of the winning vault `CandidatePath`:

```rust
let vault_root: Option<&DirPath> = discovery_result.vault().first().map(|c| c.base());
```

The cache root resolver receives this `Option<&DirPath>` (not a raw `Option<PathBuf>`).

## Integration points

- `CacheRoot` is added as a field on `DiscoveryResult`:
  ```rust
  pub struct DiscoveryResult {
      vault: Box<[CandidatePath]>,
      global: Box<[CandidatePath]>,
      cache_root: CacheRoot,   // new
  }
  ```
- `DiscoveryProcessor::finalize()` computes the `CacheRoot` from the accumulated
  vault candidates and the runtime env, then includes it in `DiscoveryResult`.
- `Bootstrapper` does not need changes — it already threads `DiscoveryResult`
  through to `BootstrapResult` consumers.
- `CacheConfig::cache_dir` is deprecated; any existing callers of `CacheConfig::cache_dir()`
  must be migrated to use `DiscoveryResult::cache_root()`.

## Agent Brief

**Category:** enhancement

**Summary:** Add `CacheRoot` to `DiscoveryResult`, produced by `DiscoveryProcessor::finalize()`, replacing the deprecated `CacheConfig::cache_dir` static relative-path field.

**Current behavior:**
`CacheConfig` holds a `CacheDir` wrapping a `RelativeDirPath` (default `.cache`). Callers must combine it with the vault root themselves. There is no env-var override and no platform-level fallback. The cache location is a config value, not a discovered value.

**Desired behavior:**
`DiscoveryResult` includes a `CacheRoot` field populated during `DiscoveryProcessor::finalize()`. Resolution follows a three-step chain: `LITHOS_CACHE_DIR` env var → `<vault_root>/.lithos/cache/` (if vault is known) → OS platform user cache fallback. The static `CacheConfig::cache_dir` field is deprecated and all callers migrated.

**Key interfaces:**
- `CacheRoot { location: CacheLocation, path: PathBuf }` — new type in `discovery/location.rs`; `PathBuf` not `DirPath` because the directory need not exist at construction
- `CacheLocation::Local(LocalCacheLocation)` | `CacheLocation::Global(GlobalCacheLocation)`
- `LocalCacheLocation::ProjectCacheDirectory` — `<vault_root>/.lithos/cache/`
- `GlobalCacheLocation::{EnvironmentOverride, PlatformUserCache}`
- `DiscoveryResult::cache_root() -> &CacheRoot` — new accessor
- `DiscoveryProcessor::finalize()` — computes and embeds `CacheRoot`; reads env override via `self.ctx.env().cache_dir()`
- Vault root derived from: `self.vault.first().map(|c| c.base())` inside `finalize()`
- `DiscoveryEnv::cache_dir: Option<PathBuf>` — new field; Bootstrapper reads `LITHOS_CACHE_DIR` and injects it
- `dirs` crate — must be added as a new dependency for `PlatformUserCache`
- `CacheConfig::cache_dir` — deprecated; callers migrated
