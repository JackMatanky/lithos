## What to build

Define the discovery submodule's core type contracts so root resolution and config file discovery become explicit, typed seams rather than implicit helper behavior.

This slice establishes the foundational enums/structs for discovery outcomes and warning reporting, including vault root resolution source annotations and config location/source metadata.

## Acceptance criteria

- [ ] A dedicated `config/discovery/` submodule is introduced and is the home of root/config discovery contracts.
- [ ] `VaultRootResolution` exists and distinguishes explicit flag, environment variable, ascending discovery, and not-found outcomes.
- [ ] `GlobalConfigLocation`, `LocalConfigLocation`, and `ConfigLocation` exist with documented precedence semantics.
- [ ] `DiscoveredConfigFile` exists and includes `location`, `base`, `path`, and `format`.
- [ ] `ConfigDiscoveryResult` exists and includes `global`, `local`, and `warnings`.
- [ ] `DiscoveryWarning` exists as a typed warning channel and includes variants for local ambiguity, format ambiguity, and case-correction diagnostics.
- [ ] Unit tests validate the shape and semantics of these contracts (not behavior of filesystem traversal yet).

## Agent Brief (Revised)

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Introduce durable discovery type contracts under `config/discovery/` for root source annotation, config location typing, and warning transport.

**Current behavior:**
Discovery contracts are implicit in `config/discovery.rs` (`GlobalDiscovery`,
`VaultDiscovery`, `DiscoveryResult`) and tightly coupled to current ingestion
flow (`Builder::load`). The contract does not encode root-resolution source,
location taxonomy, or typed ambiguity warnings required by the root-discovery
PRD.

**Desired behavior:**
A dedicated discovery contracts module defines typed, documented interfaces for
root resolution and config discovery outputs. The contracts are usable by
downstream config orchestration without requiring filesystem traversal logic in
this slice.

**Key interfaces:**
- `VaultRootResolution` with explicit variants for `--vault`,
  `LITHOS_VAULT_PATH`, ascending walk, and not-found.
- `GlobalConfigLocation`, `LocalConfigLocation`, and `ConfigLocation` with
  documented precedence semantics and deterministic ordering intent.
- `DiscoveredConfigFile { location, base, path, format }` where `base` is
  explicitly defined for local directory variants.
- `ConfigDiscoveryResult { global, local, warnings }` as the Phase 2 result
  transport type.
- `DiscoveryWarning` typed variants covering local-location ambiguity,
  multi-format ambiguity, and case-correction diagnostics.

**Acceptance criteria:**
- [ ] `config/discovery/` exists as a module boundary and houses the new
      contracts (not a flat `config/discovery.rs` contract definition).
- [ ] Root-resolution source variants are representable without lossy string
      tags and include a no-root outcome.
- [ ] Config location contracts express global vs local source space clearly
      and are documented with precedence intent.
- [ ] `DiscoveredConfigFile` and `ConfigDiscoveryResult` compile as standalone
      contract types, independent from traversal execution.
- [ ] `DiscoveryWarning` variants are typed (not free-form strings) and carry
      enough structured data for downstream diagnostics.
- [ ] Unit tests in the discovery module validate contract shape,
      invariants/semantics, and trait behavior (`Debug`, `Clone`,
      `PartialEq`/`Eq` where applicable) following unit naming standards.

**Implementation preferences (approved):**
- [ ] Prefer `pub(crate)` visibility for this slice unless broader exposure is
      required by a concrete caller.
- [ ] Start with minimal derives; add additional derives only when a concrete
      need is demonstrated.
- [ ] Use type names exactly as defined in this issue (`VaultRootResolution`,
      `GlobalConfigLocation`, `LocalConfigLocation`, `ConfigLocation`,
      `DiscoveredConfigFile`, `ConfigDiscoveryResult`, `DiscoveryWarning`).

**Out of scope:**
- Implementing ascending-walk traversal or candidate selection algorithms.
- Wiring CLI `lithos config` commands.
- Removing `vault_path` from `RawVaultConfig` (separate slice dependency).
- Changes to persistence schema/storage formats beyond what is needed to
  compile new contract types.
