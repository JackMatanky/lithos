## What to build

Remove `vault_path` from local raw config DTO/schema so vault root is exclusively runtime-discovered context from Phase 1.

This slice finalizes the circular-dependency break by ensuring local config no longer encodes root path data.

## Acceptance criteria

- [ ] `RawVaultConfig` no longer includes `vault_path`.
- [ ] Any schema/serde expectations tied to `vault_path` are removed or migrated.
- [ ] Builder/processor call paths no longer depend on `vault_path` for root determination.
- [ ] Deserialization tests prove local config without `vault_path` is valid.
- [ ] Regression tests verify root resolution remains owned by discovery outputs.
- [ ] Builder error messages using `"vault_path"` as a field name (which refer to missing discovery entry, not DTO field) are renamed (e.g., `"vault_config_file"`).

## Agent Brief

**Category:** enhancement
**Summary:** Remove `vault_path` from local raw config to finalize runtime root
ownership.

**Current behavior:**
`RawVaultConfig` still encodes root path data, preserving a circular assumption
that config defines root rather than discovery producing root.

**Desired behavior:**
Local raw config no longer contains `vault_path`; root context is sourced only
from discovery outputs.

**Impact analysis (GitNexus):** MEDIUM risk — 13 impacted symbols, 1 process
affected (`promoted_checkbox_parses_dates`). 5 direct dependents (d=1 WILL
BREAK), 8 indirect (d=2 LIKELY AFFECTED).

**Key design insight:** `raw.vault_path` is never read in production code. The
builder derives vault file path from `discovery.vault().entry().path()` — the
field was dead weight on the DTO. The `"vault_path"` strings in builder error
messages (`builder.rs:352,480`) describe a missing discovery entry, not a DTO
field; these should be renamed.
