Refactor `SchemaProcessor` to eliminate its reliance on `FsReader::metadata()`. Instead of executing redundant filesystem I/O checks during comparison, the processor must pass down and utilize the `FsMetadata` embedded inside the `FsEntry` objects produced by `DirScanner` during discovery.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** refactoring / bug
**Summary:** Eliminate redundant `FsReader::metadata()` calls in `SchemaProcessor` by threading metadata from `DiscoveryResult`.

**Current behavior:**
`SchemaProcessor` methods (specifically `classify_file_state` and the `Analysis` transition logic) accept an `&FsReader` to fetch file metadata by path. During the `Review` stage discovery, a dummy `FsReader` is currently passed, causing metadata retrieval to fail and fall back to default empty values. This breaks staleness detection for cached schemas.

**Desired behavior:**
Metadata obtained during the initial `DirScanner` pass (stored in `DiscoveryResult`) must be passed into the processing logic. All payload types (`InitialScan`, `FoundPayload`, `RebuildNodePayload`) should be populated from this discovered metadata. `FsReader::metadata()` should no longer be called within `SchemaProcessor` for standard discovery flows.

**Key interfaces:**
- `SchemaProcessor::classify_file_state`: Change signature to remove `source: &FsReader` and instead accept a mapping of `PathKey` to `FileMetadata`.
- `SchemaProcessor::from_discovery_result`: Update to extract metadata from `SchemaDiscovery` entries and pass it to the classification logic.
- `FreshPayload` & `StaleTimestampPayload`: Ensure these structs carry the metadata needed for downstream `Rebuild` or `Refresh` transitions.

**Acceptance criteria:**
- [ ] `classify_file_state` no longer takes `&FsReader`.
- [ ] `SchemaProcessor` unit tests verify that `DiscoveryResult` metadata is correctly preserved in `InitialScan` and `FoundPayload`.
- [ ] No calls to `source.metadata()` remain in `lithos-core/src/schema/schema_processor.rs` (except possibly for explicitly requested manual reloads if applicable).
- [ ] `cargo test -p lithos-core -- test_schema` passes.

**Out of scope:**
- Refactoring `PropertyBankProcessor` (handled in a separate issue).
- Changing the `DirScanner` implementation itself.
