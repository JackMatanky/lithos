## 🔴 P0 — Bugs

### 1. `Ok(_)` arm rationale and fix were wrong in Pass 1

**File**: `crates/indexer/src/scanner/walkdir.rs:65-68`

**Correction**: `FsNode` has `#[non_exhaustive]` (`crates/fs/src/entry.rs:20`).
The `Ok(_)` arm is REQUIRED by the compiler when matching a `#[non_exhaustive]`
enum across crate boundaries — it is NOT dead code. The `unreachable!()` fix
from Pass 1 would cause UB in release builds if a 3rd variant is ever added.

**Current code is correct**: graceful degradation to `Skipped` with
`UnsupportedEntryType` is the right forward-compat behavior. No code change
needed. The path loss (`PathBuf::new()`) is unavoidable since `FsNode::try_from`
consumed the `walkdir::DirEntry`.

**Action**: No code change. Document the rationale so the next reader doesn't
"fix" it back to dead-code analysis.

### 2. Catch-all error arm misclassifies non-Traversal ScanErrors

**File**: `crates/indexer/src/scanner/walkdir.rs:78`

**Current code**:
```rust
_ => (PathBuf::new(), SkipReason::PermissionDenied),
```

**Problem**: `ScanError` (`crates/fs/src/error.rs:109`) has `#[non_exhaustive]`
and 4 variants: `Traversal`, `InvalidPattern`, `UnsupportedEntryType`, `Path`.
The `_` catch-all hits `InvalidPattern` and `Path` variants today — neither is
`PermissionDenied`. Both lose their error context and surface as misleading
"permission denied".

Reachable code paths through `FsNode::try_from` (`fs/entry.rs:121-172`):
- `ScanError::Path(PathError)` — when `DirPath::try_new`/`FilePath::try_new`
  fails inside `FsNode::try_from` (e.g., path not valid UTF-8)
- `ScanError::InvalidPattern` — unlikely from walkdir path, but future
  `#[non_exhaustive]` variants would also hit this arm

**Fix**: `#[non_exhaustive` prevents exhaustive enumeration, so keep the `_`
catch-all but change `PermissionDenied` to `UnsupportedEntryType`:

```rust
Err(e) => {
    let (path, reason) = match e {
        ScanError::UnsupportedEntryType(p) => (p, SkipReason::UnsupportedEntryType),
        ScanError::Traversal { path, .. } => (path, SkipReason::PermissionDenied),
        _ => (PathBuf::new(), SkipReason::UnsupportedEntryType),
    };
    Ok(ScanEntry::Skipped(SkippedEntry { path, reason }))
}
```

### 10. `all_paths()` returns duplicates for same path in both tables

**File**: `crates/indexer/src/storage/read.rs:225-233`
**Also**: `crates/indexer/src/storage/testing.rs:158-163` (same issue in
`InMemoryRepository::all_paths()`)

**Problem**: No deduplication. `detect_deletions` processes each returned path — on
a duplicate the second pass finds the record again, duplicating the ID in
`DeletedNodes`.

**Fix**: Dedup via `HashSet`:

```rust
// read.rs
fn all_paths(&self) -> Result<Box<[PathKey]>, IndexerRepositoryError> {
    self.store.read(|tx| {
        let file_path_table = tx.inner.open_table(FILE_ID_BY_PATH.definition())?;
        let dir_path_table = tx.inner.open_table(DIR_ID_BY_PATH.definition())?;
        let mut paths = Vec::new();
        let mut seen = std::collections::HashSet::new();
        for result in file_path_table.iter()? {
            let (path, _) = result?;
            let pk = path.value().into_inner();
            if seen.insert(pk.clone()) {
                paths.push(pk);
            }
        }
        for result in dir_path_table.iter()? {
            let (path, _) = result?;
            let pk = path.value().into_inner();
            if seen.insert(pk.clone()) {
                paths.push(pk);
            }
        }
        Ok(paths.into_boxed_slice())
    }).map_err(Into::into)
}
```

Same pattern in `testing.rs`.

### 19. `DuplicatePath` error variant is never constructed

**File**: `crates/indexer/src/error.rs:39-41`

**Problem**: `IndexerRepositoryError::DuplicatePath(PathKey)` is defined but
never constructed by the indexer's `WriteRepository` implementations.
`write.rs::save_file_in_tx` does NOT check for existing paths before writing —

primary record.

**Fix**: Either (a) enforce uniqueness in `save_file_in_tx` and construct
`DuplicatePath`, or (b) remove the variant entirely. Option (a) is recommended
for correctness:

```rust

let existing = path_table.get(DbPathKey::from(record.path()))?;

    if existing_id.value() != record.id() {
        return Err(IndexerRepositoryError::DuplicatePath(record.path().clone()));
    }
}
```

## TDD Implementation Plan

### Methodology

Vertical tracer-bullet slices: one behavior → one RED test → minimal GREEN →
commit. **No horizontal slicing** (not "all tests then all code"). Tests verify
behavior through public/crate interfaces, not implementation details. Each slice
ends GREEN with `cargo test -p trace-indexer` passing.

### Classification of the 27 items by TDD shape

Not every item is a RED→GREEN cycle. They split into four shapes:

| Shape | Items | Approach |
| ----- | ----- | -------- |
| **Behavioral (RED→GREEN)** | 2, 19, 20 | Failing test first, then code. New behavior. |
| **Test-only (RED, GREEN already passes)** | 3, 4, 5, 6, 7, 21 | Add test; it should pass against current correct code. If it fails, that surfaces a real bug. |
| **Refactor-under-tests (GREEN-stays-GREEN)** | 8, 9, 10, 13 | Behavior unchanged; existing + new tests are the safety net. Refactor, keep green. |
| **Non-behavioral (no test)** | 1, 11, 12, 14, 15, 16, 17, 18, 22, 23, 24, 25, 26, 27 | Docs, dead-code deletion, lint hygiene, `#[inline]`, comments. Full suite is the regression guard. |

### Design decisions (SETTLED)

All three confirmed. Locked for implementation.

**A. Failure model (#6 vs #20) — two layers. DECIDED.**
- **Stream errors** (`self.scanner.walk(...)?` at `service.rs:81`, `result?` at
  `:82`): a `ScannerError` means traversal itself broke → **aborts** the run
  (#6 tests this).
- **Per-entry errors** (`into_branch(...)?`, `into_comparison_branch(...)?`,
  `into_indexed(...)?` at `:84,88,94,99,105`): an `IndexerError` for ONE entry →
  **soft-fail** into `report.failures`, continue scanning.
- **Recoverable vs fatal split**: `IndexerError::Path(_)` is per-entry-recoverable
  (soft-fail). `IndexerError::Repository(_)` is fatal (abort — a DB failure on one
  entry will recur on all). `IndexerError::Scanner(_)` does not arise here (stream
  layer). Implement via a helper that classifies the error, e.g.
  `fn is_recoverable(e: &IndexerError) -> bool { matches!(e, IndexerError::Path(_)) }`.

**B. `IndexNodeFailure` shape (#20) — reshape to path + error. DECIDED (b1).**
- Change `IndexNodeFailure` from `{ id: FsRecordId, kind: FsRecordType, error }`
  to `{ path: PathBuf, error: Box<str> }`, matching `SkippedEntry`.
- Rationale: a pre-classification failure has no real id and no known
  file-vs-dir kind; fabricating `FsRecordId::new()` + `FsRecordType::File` is
  misleading.
- **Ripple**: this removes the only non-test use of `FsRecordType` outside
  `report.rs`. Re-check #18 — after this change, `FsRecordType` may become
  genuinely unused. If so, in Slice 9 either delete `FsRecordType` entirely or
  keep it only if issue 07 needs it (decide at that point; do not pre-emptively
  keep dead code).

**C. #2 testability — extract pure classifier. DECIDED.**
- Extract the error→`SkippedEntry` mapping into a pure private fn and unit-test
  it directly (real `WalkdirAdapter` can't practically produce
  `ScanError::Path`/`InvalidPattern`):
```rust
fn classify_scan_error(e: ScanError) -> SkippedEntry { ... }
```
Deep-module improvement: small surface, testable core.

## 🔴 P0 — Correctness

### R1. `detect_deletions` silently swallows repository errors

**File**: `crates/indexer/src/service.rs:188-198`

```rust
if let Ok(Some(file)) = self.repo.find_file_by_path(path) {
    file_ids.push(file.id());
} else if let Ok(Some(dir)) = self.repo.find_dir_by_path(path) {
    dir_ids.push(dir.id());
} else { /* Neither file nor dir — stale path, skip */ }
```

`find_*_by_path` returns `Result<Option<_>, IndexerRepositoryError>`. `if let
Ok(Some(..))` discards the `Err` arm: a `DbError::Deserialization` (reachable —
`read.rs:36`) or any storage error on one record is **silently reclassified as
"path absent → skip"**. This contradicts the crate's own settled failure model
(06.5 decision A: "`IndexerError::Repository(_)` is fatal → abort"). A corrupt
record can cause a *missed deletion* or mask DB corruption the abort path is meant
to surface. The `run()` loop is rigorous (`Err(other) => return Err(other)`,
`service.rs:102`) then this sibling fn throws that discipline away.

**Rule**: RBP ch.4 (never discard `Result`); CONTEXT failure model. **06.5 missed this.**
**Fix**: propagate with `?` on both lookups (or `match` and abort on `Err`).
**Test first**: repo double whose `find_file_by_path` returns `Err` → assert `run()`
aborts with `IndexerError::Repository`. Fails today.

## 🟡 P2 — Design & Architecture

### R2. `&dyn Repository` is a real least-privilege regression

**File**: `builder.rs:187,235,295,346`; `service.rs:152`

Read-only stages (`into_comparison_branch`) receive `&dyn Repository` (read+write)
when they only call `find_*_by_path`. The prior `&impl ReadRepository` /
`&impl WriteRepository` split encoded capability in the type; collapsing to the
unified trait hands write capability to read-only code. Separable from the dispatch
choice (R3) — keep `dyn`, narrow the trait.

**Rule**: hex (ports encode capability); RBP ch.6.
**Fix**: `into_comparison_branch(&self, repo: &dyn ReadRepository)`.
**Severity P2** (no current misuse; removes a compile-time guard the codebase had).

### R3. Trait-object dispatch — defensible, but rationale comment is imprecise

**File**: `service.rs:35-42`

The choice is sound for a deep, disk-bound module (not disputed). But the doc says
"two vtable calls per scan iteration" — there are actually **three** dyn indirections
per entry (scanner walk + two repo lookups in the builder). Correct the comment;
no behavioral change. **Rule**: RBP ch.6/ch.8.

### R4. `write.rs` duplicate-path: commits a no-op transaction instead of rolling back

**File**: `write.rs:30-37,246-257,266-275,311-337`

Verified `Store::write` commits on closure `Ok` (`db/src/core.rs:84-86`). On
conflict the code sets `rejected = Some(path); return Ok(())` → **commits an empty
write transaction**, then surfaces the error via a captured `Option` side-channel.

- (a) No partial writes on conflict — **correct** (conflict checked before any insert;
  `save_many_records` validates the whole batch first, `write.rs:315-326`).
- (b) Same-id update exempt — **correct** (`write.rs:132`).
- (c) Racy? — **No**, redb single-writer; read happens inside the active write tx.
- (d) Clearest expression? — **No. Genuine smell.** Committing a tx to express
  "reject and change nothing" is backwards. Root cause: `Store::write`'s closure
  error type is hardwired to `DbError`, which has no `DuplicatePath`, so a *domain*
  rejection is forced through `Option<PathKey>`. Morally the same as the
  sentinel-`DbError` hack 06.5 explicitly rejected. Also wasteful (redundant fsync
  per rejected write).

**Rule**: RBP ch.4 (model errors in the type); hex (domain errors not smuggled around port).
**Decision (settled with user — see "Decisions" below)**: fix at source — make
`Store::write` generic over the closure error (`F: FnOnce(&mut WriteTx) ->
Result<R, E>` where `E: From<DbError>`). Cross-context change to `traces_db` →
**requires an ADR + `impact` on the DB crate before edit**. Fallback if DB churn is
unwelcome: keep the `Option` channel but add a `// ponytail:`-style comment naming
the DB-error-type constraint as the reason and recording the generic-error upgrade path.

### R5. `IndexReport::new` is `pub` — over-exposes the domain

**File**: `report.rs:29` (also `ScanFilters::new` `pub`, `scan.rs:24`)

7-arg `pub` constructor lets a consumer fabricate inconsistent reports
(`scanned=0, new=99`). The cli test reaches into it (`cli/.../index.rs:181-206`) —
a test driving production visibility. Contrast the correctly `pub(crate)`
`IndexResult::new`/`IndexedNodes::new`/`DeletedNodes::new`.

**Rule**: hex (domain integrity); CONTEXT.
**Fix**: make `IndexReport::new` `pub(crate)`; give the cli test a `#[cfg(test)]`
builder/helper instead of the domain constructor.

### R6. `error.rs` module doc claims a separation the type contradicts

**File**: `error.rs:1-6`

"strictly separates internal scanner/traversal errors from local database
(repository) errors" — but `IndexerError` has a third arm `Path(PathError)`
(`error.rs:26`), the linchpin of the soft-fail model. Stale after the reshape.
**Rule**: RBP ch.8; doc dimension. **Fix**: rewrite the module doc to include `Path`.
