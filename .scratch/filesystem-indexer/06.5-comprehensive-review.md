## Executive Summary

The indexer is structurally sound — hexagonal boundaries respected, ports and adapters cleanly separated, comprehensive redb table tests, no `unwrap()` in production code. However, 11 items across 4 severity levels must be resolved before moving to issue 07. None are blocking in the sense of "the indexer doesn't work" — they are blocking in the sense of "we committed to best-practice Rust and these are the gaps."

Priority order: bugs → test gaps (can hide bugs) → architecture (compounds over time) → quality/nits.

## 🔴 P0 — Bugs

### 1. Dead `Ok(_)` arm in `ScanEntry::try_from` — silently discards state

**File**: `crates/indexer/src/scanner/walkdir.rs:65-68`
**Current code**:
```rust
Ok(_) => Ok(ScanEntry::Skipped(SkippedEntry {
    path: PathBuf::new(),
    reason: SkipReason::UnsupportedEntryType,
})),
```
**Problem**: `FsNode` has exactly two variants (`File(FileNode)`, `Dir(DirNode)`). The `Ok(_)` catch-all is unreachable. If `#[non_exhaustive]` is the concern (it is — `fs/entry.rs:20`), this arm MUST use `unreachable!()` so a new `FsNode` variant causes a compile-visible panic during testing, not a silent `SkippedEntry` with `PathBuf::new()`.

**Fix**:
```rust
Ok(_) => {
    // #[non_exhaustive] forward-compat — all known FsNode variants handled above
    unreachable!("FsNode::File and FsNode::Dir are the only variants");
}
```

### 2. Catch-all error arm misclassifies non-Traversal ScanErrors

**File**: `crates/indexer/src/scanner/walkdir.rs:77-79`
**Current code**:
```rust
_ => (PathBuf::new(), SkipReason::PermissionDenied),
```
**Problem**: `ScanError` has four variants: `Traversal { path, source }`, `InvalidPattern { pattern, message }`, `UnsupportedEntryType(PathBuf)`, `Path(PathError)`. The `_` catch-all hits `InvalidPattern` and `Path` variants — neither is `PermissionDenied`, and both lose their path/debug info. An `InvalidPattern` error surfaces as "permission denied" with empty path — actively misleading.

**Fix**: Enumerate all variants explicitly:
```rust
ScanError::InvalidPattern { pattern, message } => {
    (PathBuf::new(), SkipReason::UnsupportedEntryType)
}
ScanError::Path(err) => {
    (PathBuf::new(), SkipReason::UnsupportedEntryType)
}
```
Or add `#[non_exhaustive]` awareness: log the raw error string and use a generic skip reason, but never `PermissionDenied` unless it actually was a permission error.

The `ScanError::Traversal` arm already correctly handles `PermissionDenied` (lines 70-76) — move it before the catch-all and let it fall through to `UnsupportedEntryType` for other errors.

## 🟡 P2 — Architecture & Safety

### 8. `IndexerService<S, R>` → trait-object dispatch to cut monomorphization

**File**: `crates/indexer/src/service.rs:39-55`
**Problem**: `IndexerService<S: ScannerPort, R: Repository>` monomorphizes the full 880-line module per instantiation pair. One production pair (WalkdirAdapter + RedbRepository), one test pair (MockScanner + InMemoryRepository). The test monomorphization doesn't affect the binary (test code is stripped), but compile time doubles.

**Fix**: Use `Box<dyn ScannerPort>` and `Box<dyn Repository>`:
```rust
pub struct IndexerService {
    vault_root: DirPath,
    scanner: Box<dyn ScannerPort>,
    repo: Box<dyn Repository>,
}

impl IndexerService {
    pub fn new(vault_root: DirPath, scanner: Box<dyn ScannerPort>, repo: Box<dyn Repository>) -> Self { ... }
}
```
Trade-off: Two vtable calls per scan-loop iteration (`scanner.walk()` + each `repo.find_*`). For a disk-bound operation this is noise. Benefit: single monomorphization, smaller binary, faster compiles, concrete type in public API (no turbofish).

**But**: The test `MockScanner` and `InMemoryRepository` already implement the traits. `WalkdirAdapter` implements `ScannerPort`. `RedbRepository` implements `Repository`. No existing code changes except the constructor call site in `crates/app/src/index.rs`.

**Deferred alternative**: If compile time is not yet a measured problem, document as a known cost. The `dyn` conversion is mechanical when needed. **Recommend doing it now** — it's a 10-line change and the `app` crate already owns the only constructor call site.

### 9. `run()` takes `&self` — no static mutual exclusion

**File**: `crates/indexer/src/service.rs:68`
**Problem**: `run(&self, ...)` → all writes go through interior mutability (`RwLock`/redb `WriteTransaction`). Nothing prevents `service.run(...)` from being called concurrently with `service.detect_deletions(...)`.

**Fix**: Change to `&mut self`:
```rust
pub fn run(&mut self, scope: &IndexScope, opts: IndexOptions) -> Result<IndexResult, IndexerError>
```
The borrow checker now guarantees single-threaded access. The trade-off is ergonomic: callers can't share the service across threads or call `run()` twice without `&mut`. For a short-lived CLI pipeline that's called once per command invocation, this is the correct trade-off.

**If deferred**: Add a doc comment warning: `// SAFETY: run() uses interior mutability — do not call concurrently. The redb WriteTransaction provides runtime mutual exclusion, but the type system does not enforce it.`

### 10. `all_paths()` returns duplicates for same path in both tables

**File**: `crates/indexer/src/storage/read.rs:225-233`
**Problem**: File paths and dir paths are collected from separate tables. No deduplication. `detect_deletions` (`service.rs:153-163`) processes each returned path — on a duplicate, the second pass finds the record again (still in the table), potentially duplicating the ID in `DeletedNodes`.

**Fix**: Deduplicate in `all_paths()`:
```rust
let mut paths: Vec<PathKey> = Vec::new();
let mut seen = std::collections::HashSet::new();
for result in file_path_table.iter()? {
    let (path, _) = result?;
    if seen.insert(path.value().into_inner()) {
        paths.push(path.value().into_inner());
    }
}
// same for dir_path_table
```
Or document as known limitation: `/// # Known limitation: paths present in both FILE_ID_BY_PATH and DIR_ID_BY_PATH are returned once per table. Dedup at the caller if needed.`

### 11. `clear()` partial-failure surface

**File**: `crates/indexer/src/storage/write.rs:294-316`
**Problem**: 16 sequential table operations (8 `delete_table` + 8 `open_table`) in a single write transaction. If `open_table` fails after `delete_table` succeeded for tables 1–5, tables 6–8 are deleted but not recreated. Redb rollback *should* handle this (single tx → all-or-nothing), but redb's replay-log correctness for `delete_table`+`open_table` in the same tx is an internal implementation detail.

**Fix**: Add a documenting comment:
```rust
// All 8 delete+recreate pairs execute within a single WriteTransaction.
// redb guarantees atomicity: on rollback, all deletions are reverted.
// If any open_table() fails, the tx aborts and all prior deletes are undone.
```
No code change needed — just make the assumption explicit so future maintainers don't refactor `clear()` into multiple transactions.

## 🟡 P3 — Code Quality

### 12. `#[inline]` on hot deserialization helpers

**File**: `crates/indexer/src/storage/read.rs:33-41`
**Problem**: `deserialize_file` and `deserialize_dir` are called once per record on every `find_*` read. Without `#[inline]`, the compiler may not specialize the `rkyv::from_bytes` monomorphization for `FileRecord`/`DirRecord` at each call site.

**Fix**:
```rust
#[inline]
fn deserialize_file(bytes: &[u8]) -> Result<FileRecord, DbError> { ... }
#[inline]
fn deserialize_dir(bytes: &[u8]) -> Result<DirRecord, DbError> { ... }
```

### 13. Builder file/dir structural duplication

**File**: `crates/indexer/src/builder.rs:280-332` vs `335-384`
**Problem**: `FilePersistence::into_indexed` and `DirPersistence::into_indexed` are ~50 lines each, identical except for:
- `FileName::new` vs `DirName::new` (type API diff)
- `FileFormat::from_extension` vs no format for dirs
- `FileRecord::new` vs `DirRecord::new` (type constructor)
- `repo.save_file` vs `repo.save_dir`

**Fix**: Extract a generic helper. Not worth introducing a `NodeRecord` trait for two implementations, but the `parent_id`, `name`, and `record` construction blocks can be inlined through a closure or macro:
```rust
fn build_record<T, F>(
    node_path: &trace_fs::DirPath,  // both FileNode and DirNode have .path()
    path_key: &PathKey,
    id: FsRecordId,
    parent_id: FsParentId,
    metadata: impl Clone,
    build: F,
) -> T
where F: FnOnce(FsRecordId, FsParentId, PathKey, ..., impl Clone, SystemTime) -> T
{ ... }
```
**Ponytail**: Acceptable duplication for 2 impls. Add a `record_from_parts` helper to collapse the common parent/name extraction, but keep record-type construction distinct.

### 14. Module-level `#[expect(clippy::arithmetic_side_effects)]` is too broad

**File**: `crates/indexer/src/service.rs:8-11`
**Problem**: Suppresses the lint for ALL 880 lines. Intended for 3 counter increments in `IndexCollector::record`.

**Fix**: Move to per-expression `#[expect(...)]` on each of the 3 `+= 1` operations in `IndexCollector::record` (`service.rs:198-200`, `213-215`). Remove the module-level suppression.

### 16. `WalkdirAdapter` ZST doc is misleading

**File**: `crates/indexer/src/scanner/walkdir.rs:14-17`
**Problem**: "Zero-size struct" is a property of the struct definition (no fields), not a design decision to communicate to readers. It implies the reader should care about the struct layout, which is irrelevant at this level.

**Fix**: Rephrase to communicate intent:
```rust
/// Walkdir-based filesystem traversal adapter.
///
/// No vault knowledge lives here — receives the resolved `DirPath` per call
/// via the port contract. Stateless: all traversal parameters are passed

```

### 17. `test_indexer_exports` doesn't verify production re-exports

**File**: `crates/indexer/src/lib.rs:38-50`
**Problem**: The test checks `#[cfg(test)]` visibility (`pub(crate) use storage::InMemoryRepository`) but never checks that the 15 `pub use` re-exports in `lib.rs:25-36` actually resolve. A missing re-export would only fail at the `crates/app` or `crates/cli` level, not in `crates/indexer` tests.

**Fix**: Add a simple compile-test pattern:
```rust
const _: fn() = || {
    // Production exports must resolve
    let _: FsRecordId = todo!();
    let _: ScanEntry = todo!();
    let _: IndexResult = todo!();
```

Or keep as-is — the `app` crate compilation will catch it. Move to P4.
