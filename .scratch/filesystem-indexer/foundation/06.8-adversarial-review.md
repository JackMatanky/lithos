## Part B — NEW findings (this pass)

Severity: **P0** correctness · **P1** test/doc defect that can hide regressions ·

### 🔴 P1 — Test & doc defects

#### A1. `pretty_assertions` conversion (R7) is ~86% incomplete — crate-wide unit.md violation persists

**Files**: `service.rs` (45 asserts), `model.rs` (14), `storage/read.rs` (14),
`storage/write.rs` (10), `storage/testing.rs` (4), `summary.rs` (8), `entry.rs` (7),
`scanner/walkdir.rs` (6). Grep: only `report.rs`, `builder.rs`, `storage/contract.rs`
import `pretty_assertions` (`rg pretty_assertions crates/indexer` → 5 hits in 3 files).

unit.md:26,113 mandates `pretty_assertions` for **all** equality assertions. The 06.7 plan
(Slice 0.1 + Phase 3: "convert bare→pretty asserts per module as you touch it") added the
dev-dependency and converted three modules, then the sweep stalled. **~108 `std::assert_eq!`/
`assert_ne!` across 8 modules remain non-conformant** — including the most important file,
`service.rs`. This is the single highest-volume standard violation in the crate and was
under-reported by 06.6/06.7 (which treated R7 as "fixed").
**Rule**: unit.md:26,113,148. **Fix**: `use pretty_assertions::{assert_eq, assert_ne};` per
test module and convert; mechanical, clippy/test-guarded.

#### A2. `port.rs` has a zero-assertion test whose name lies about its coverage — ALL FOUR PRIOR PASSES MISSED THIS

**File**: `port.rs:99–105`.

```rust
#[test]
fn yields_file_dir_and_skipped_variants() {
    let _entry = ScanEntry::Skipped(SkippedEntry { path: "/tmp/test".into(),
        reason: SkipReason::PermissionDenied });
}
```

The test **constructs one `Skipped` variant and asserts NOTHING** — it can never fail. The
name promises file + dir + skipped coverage; the body exercises only `Skipped` and verifies
no behavior. This is the exact "assertion-only smoke test" anti-pattern unit.md:161 forbids,
in its most degenerate form (zero assertions). 06.5/06.6/06.7 all swept `port.rs` and none
flagged it.
**Rule**: unit.md:161; unit-naming.md:253 (name must not bundle/lie). **Fix**: either delete
it (the `ScanEntry` variants are exercised end-to-end in `service.rs`/`walkdir.rs`) or replace
with a real per-variant assertion. Recommend delete — it adds no coverage.

#### A3. `port.rs:84` `scanner_port_can_be_mocked` is an assertion-only mock smoke test

**File**: `port.rs:83–97`. Builds a mockall `MockScannerPort`, calls `walk`, then
`assert!(result.is_ok())` on a mock wired to return `Ok`. It asserts the mock framework works,
not domain behavior. Combined with A2, `port.rs`'s flat `mod tests` (2 tests) carries zero
real coverage. **Rule**: unit.md:161. **Fix**: drop or fold into a real walk test. (Lower
priority than A2 — at least this one has an assertion.)

#### A4. Private `Result`-returning fns lack `# Errors` sections (docs build with `--document-private-items`)

The crate documents private items, so the `# Errors` mandate (RBP ch.8;
`missing_errors_doc`) applies to them too. Missing on:
- `scanner/walkdir.rs:61` `map_error` (genuinely returns `Err`) — **no doc at all**.
- `storage/read.rs:33,39` `deserialize_file`/`deserialize_dir` — no doc, return `Result`.
- `storage/write.rs:30–226` `load_*_delete_context`, `*_in_tx`, `*_graph` — return `Result`,
  no `# Errors`.

Low individual severity (trivial helpers) but a consistent gap the standard names explicitly.
**Rule**: RBP ch.8. **Fix**: add one-line `# Errors` to each, or accept as flag-and-leave
(see Disposition). Note: `try_from` (`walkdir.rs:87`) is a separate issue — see A7.

### 🟡 P2 — Design / architecture

#### A5. Storage adapter writes/deletes are entirely uninstrumented (tracing gap)

**Files**: all of `storage/` (`rg 'tracing|instrument|debug!|info!|warn!' crates/indexer/src/storage` → 0 hits).

`service.rs::run` is `#[tracing::instrument]` with debug/warn/info events (good), but the
persistence boundary — `save_file`, `save_dir`, `delete_*`, `save_many_records`, `clear`
(`write.rs:228–379`) — emits nothing. For a layer doing multi-table transactional mutations
and **rejecting duplicate paths** (a domain-meaningful event worth a `warn!`/`debug!`), the
absence of any span/event is a real observability gap. The handoff anticipated this; confirmed
real. No PII concern in adding it (paths are already in `service.rs` spans).
**Rule**: hex (adapters are the IO boundary worth observing); RBP ch.8. **Severity P2**
(observability, not correctness). **Fix**: add a `debug!` per write/delete and a `warn!` on
`DuplicatePath` rejection, or explicitly decide instrumentation lives only at the service
layer and document that choice.

#### A6. R20 fix leaves one residual coupling undocumented at the call site

**File**: `service.rs:113–124`.

The R20 fix is correct, but its safety still rests on an **unstated** invariant: only
`IndexerError::Path` is soft-failed, and `scan_entry_path_key` recomputes the key
**independently** of the failed classification. If a future recoverable variant is added whose
key *is* computable and *is* stored, the insert protects it — good. But if `into_indexed`
(which writes) were ever folded into the soft-fail set, a *partial* write could leave the repo
mutated while the entry is also marked "seen", masking a real deletion. The `service.rs:113–116`
comment explains the `None` case but not this "only-pre-persistence errors may be soft-failed"
constraint. R20 in 06.7 explicitly called this the subtlest interaction; the code comment
under-documents it.
**Rule**: RBP ch.8 (document non-obvious invariants in code). **Severity P2** (latent; safe
today). **Fix**: extend the comment at `service.rs:125–131` to state "only pre-persistence
(`Path`) errors are recoverable; any error that may have already mutated the repo must abort,
because marking a partially-written entry 'seen' would hide a needed deletion."

#### A7. `TryFrom<walkdir::DirEntry> for ScanEntry` never returns `Err` — a `From` would be more honest

**File**: `scanner/walkdir.rs:83–102`. Every arm of `try_from` returns `Ok(...)` (errors are
mapped to `Ok(ScanEntry::Skipped(..))`). The `TryFrom`/`Result<Self, ScannerError>` signature
advertises a fallibility the impl never exercises, and forces the `walk` mapper (`:116–119`)
to thread a `ScannerError` that this path can't produce. **Rule**: RBP ch.4 (model the type to
match behavior). **Severity P2** (mildly misleading API surface, internal-only). **Fix**:
consider `From<walkdir::DirEntry>` and let `walk` distinguish the genuinely-fallible
`map_error` path (which *does* return `Err`) from the infallible conversion. Flag-and-leave is
defensible (the symmetry with `map_error` reads cleanly), but note it.

## Part C — Cross-context observation (out of scope for the indexer crate, recorded so it isn't lost)

#### A14. ADR 025's new capability was applied to the indexer but NOT to `note`, which has the identical smell

**File**: `crates/note/src/storage/write.rs:63–91,98,120` (+ module doc `:7–16`).

`note`'s `save`/`save_many` enforce path-uniqueness via `assert_path_available`, which runs in
a **separate read transaction** *before* the write closure and returns
`NoteRepositoryError::DuplicatePath` out-of-band. The module doc itself (`:13–16`) admits the
resulting **TOCTOU window**. This is the same class of problem ADR 025 fixed for the indexer:
with `Store::write<R, F, E>(E: From<DbError>)`, the conflict check could move *inside* the
write closure returning `Result<NoteId, NoteRepositoryError>`, rejecting with `DuplicatePath`
and rolling back atomically — closing the window. The new capability went **unused** for note.

**Disposition**: pre-existing in `note` (NOT introduced by the indexer work), and safe in
practice under redb's single-writer serialization. ADR 025 deliberately scoped itself to the
indexer's motivating case. Record as a **follow-up for the note context**, not an indexer
defect. Verified: schema / settings / template / vault write paths have **no** equivalent
side-channel (pure upserts or in-tx version allocation) — clean.

## Part D — What is genuinely clean (held to the highest standard)

- **`lib.rs`**: idiomatic export guard (`#[expect(dead_code, reason=…)]`, compile-time),
  `#![deny(unused_crate_dependencies)]` with a documented reason, no redundant runtime test.
  (Uses `#![feature(trivial_bounds)]` — nightly; pre-existing crate choice, flag-only.)
- **`repository.rs`**: clean ReadRepository / WriteRepository / Repository segregation; blanket
  impl behind a `const _` compile guard; `# Errors` on every trait method; no redb/rkyv leak.
- **`error.rs`**: 3-arm `IndexerError` with accurate module doc; `IndexerRepositoryError`
  wraps `DbError` transparently with the boundary comment "redb and rkyv types never appear
  here" (`:32`) — and they don't.
- **`builder.rs`**: typestate pipeline is sound (5 states, illegal transitions uncompilable);
  R2 narrowing correct; tests restructured to AAA + verb-first + `pretty_assertions`.
- **`summary.rs`, `storage/tables.rs`, `storage/contract.rs`**: docs accurate, structure
  canonical (contract.rs is the model — run against BOTH adapters, diagnostic asserts).
- **Hexagonal integrity overall**: ports encode capability (read vs write vs unified), domain
  models are private-field + validated-constructor, no adapter detail leaks through the port,
  errors are typed and not smuggled (the R4 fix removed the last smuggle). The architecture is
  in good shape.
