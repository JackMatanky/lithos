# Add `HasContentHash` / `HasContentHashMut` traits

## What to build

Define `HasContentHash` and `HasContentHashMut` traits in `content_hash.rs` that capture the content-hash access pattern currently duplicated across the codebase.

`HasContentHash` should expose:
- `fn content_hash(&self) -> &Blake3Hash`
- Provided default: `fn is_content_match(&self, hash: &Blake3Hash) -> bool { self.content_hash().is_match(hash) }`

`HasContentHashMut` should extend `HasContentHash` with:
- `fn set_content_hash(&mut self, hash: Blake3Hash)`

Then implement these traits on the following types:

- `Blake3Hash` (trivially — `content_hash()` returns `&self`, `set_content_hash` replaces bytes)
- `HashRecord` (delegates `content_hash()` to existing `content()` getter, `set_content_hash` updates the `content` field)
- `RawFileVersion` (delegates `content_hash()` to existing `content_hash()` getter, `set_content_hash` updates the `content_hash` field)

Types explicitly NOT implementing the traits (keep existing methods):
- `ArchivedHashRecord` — rkyv archived types can't easily implement non-rkyv traits; existing `is_content_match` stays as-is
- `SchemaVersion` / `PropertyBankVersion` — they own `HashRecord`, not a direct `Blake3Hash`; they get `is_content_match` through composition
- `ArchivedSchemaVersion` / `ArchivedPropertyBankVersion` — same reasoning

## Acceptance criteria

- [x] `HasContentHash` trait defined in `content_hash.rs` with `content_hash()` and default `is_content_match()`.
- [x] `HasContentHashMut` trait defined in `content_hash.rs` extending `HasContentHash` with `set_content_hash()`.
- [x] `Blake3Hash`, `HashRecord`, and `RawFileVersion` implement both traits.
- [x] No regressions in existing `is_content_match` call sites.
- [x] No changes to `ArchivedHashRecord`, schema view types, or their `is_content_match` methods.
- [x] `cargo clippy -p lithos-core --all-targets -- -D warnings` passes.
- [x] `cargo test -p lithos-core` passes.

## Agent Brief

**Category:** enhancement
**Summary:** Add `HasContentHash` / `HasContentHashMut` traits in `content_hash.rs` and implement on `Blake3Hash`, `HashRecord`, `RawFileVersion`

**Current behavior:**
Three unrelated types (`Blake3Hash`, `HashRecord`, `RawFileVersion`) each define `is_content_match` independently. `HashRecord` delegates to `Blake3Hash::is_match`, `RawFileVersion` uses `==`. There is no shared trait capturing the "has a content hash and can compare it" pattern.

**Desired behavior:**
`HasContentHash` and `HasContentHashMut` traits defined in `content_hash.rs` capture the shared pattern. The three candidate types implement them. Default `is_content_match` delegates to `Blake3Hash::is_match`. Existing method signatures and call sites are preserved through the trait impls.

**Key interfaces:**
- `HasContentHash` trait in `support::content_hash`: `fn content_hash(&self) -> &Blake3Hash` + default `fn is_content_match(&self, hash: &Blake3Hash) -> bool`
- `HasContentHashMut` trait in `support::content_hash`: extends `HasContentHash`, adds `fn set_content_hash(&mut self, hash: Blake3Hash)`
- `Blake3Hash` impl: `content_hash()` returns `&self`, `set_content_hash` replaces `self.0`
- `HashRecord` impl: `content_hash()` returns `self.content()`, `set_content_hash` sets `self.content`
- `RawFileVersion` impl: `content_hash()` returns `self.content_hash()`, `set_content_hash` sets `self.content_hash`
