# Markdown Note Domain Components

## Design Boundary

This model separates three concerns:

1. **Parser layer** — understands Markdown/GFM syntax.
2. **Domain layer** — models semantic note concepts.
3. **Persistence/read-model layer** — stores query-optimized database views.

The domain should not become a Markdown AST. Parser-level blocks such as paragraphs, code blocks, tables, HTML blocks, and thematic breaks stay outside the note domain unless they become semantically meaningful.

---

# 1. Domain Aggregate

## `Note`

```rust
pub struct Note {
    pub id: FsRecordId,
    pub path: FilePath,
    pub frontmatter: Option<Frontmatter>,
    pub body: NoteBody,
}
```

### Definition

`Note` is the aggregate root. It represents one markdown note as a semantic domain object.

### Purpose

Owns the note’s identity, path, frontmatter, and semantic body.

### Capabilities

```rust
impl Note {
    pub fn headings(&self) -> &[Heading];
    pub fn sections(&self) -> &[Section];
    pub fn list_items(&self) -> &[ListItem];
    pub fn links(&self) -> &[Link];
    pub fn tags(&self) -> &[Tag];

    pub fn tasks(&self) -> impl Iterator<Item = &ListItem>;
    pub fn root_sections(&self) -> impl Iterator<Item = &Section>;
    pub fn root_list_items(&self) -> impl Iterator<Item = &ListItem>;
    pub fn frontmatter_properties(&self) -> Option<&PropertySet>;
    pub fn all_inline_fields(&self) -> impl Iterator<Item = &PropertyEntry>;
}
```

### Notes

`Note` should expose simple methods first. Do not introduce helper wrapper types unless they carry useful context beyond `&Note`.

# 2. Identity Components

## `NoteId`

```rust
pub struct NoteId(uuid::Uuid);
```

### Definition

Globally unique identity for a note aggregate.

### Purpose

Used to identify notes independently of path changes.

### Capabilities

- Stable aggregate identity.
- Safe cross-note references.
- Suitable for persistence.

---

## `LocalElementId`

```rust
pub struct LocalElementId(u64);
```

### Definition

Small deterministic ID for elements inside a single note.

### Purpose

Used as the internal identity basis for headings, sections, list items, and links.

### Recommended Generation

Derive from:

```text
element kind + source span start byte
```

For example:

```rust
pub enum LocalElementKind {
    Heading,
    Section,
    ListItem,
    Link,
}
```

### Capabilities

- Smaller than UUID.
- Deterministic across reparsing when source positions remain stable.
- Verifiably unique within a note when generated by the note builder.

---

## Typed Local IDs

```rust
pub struct HeadingId(LocalElementId);
pub struct SectionId(LocalElementId);
pub struct ListItemId(LocalElementId);
pub struct LinkId(LocalElementId);
```

### Definition

Type-safe wrappers around `LocalElementId`.

### Purpose

Prevents mixing unrelated IDs.

### Notes

No `TagId` is recommended unless tags become independently editable/addressable entities.

### Capabilities

# 4. Frontmatter and Properties

## `Frontmatter`

```rust
pub struct Frontmatter {
    pub properties: PropertySet,
    pub span: SourceSpan,
}
```

### Definition

The optional frontmatter region of a markdown note.

### Purpose

Represents the single frontmatter block allowed at the top of a markdown file.

### Capabilities

- Owns note-level declared properties.
- Preserves source location.
- Supports nested property structures.

---

## `PropertySet`

```rust
pub struct PropertySet {
    pub entries: Vec<PropertyEntry>,
}
```

### Definition

A collection of properties owned by a domain object.

### Purpose

Used by frontmatter and list items.

### Capabilities

```rust
impl PropertySet {
    pub fn get(&self, key: &PropertyKey) -> Option<&PropertyValue>;
    pub fn contains_key(&self, key: &PropertyKey) -> bool;
    pub fn iter(&self) -> impl Iterator<Item = &PropertyEntry>;
    pub fn is_empty(&self) -> bool;
}
```

---

## `PropertyEntry`

```rust
pub struct PropertyEntry {
    pub key: PropertyKey,
    pub value: PropertyValue,
}
```

### Definition

One key-value property.

### Purpose

Represents frontmatter fields and inline fields.

---

## `PropertyKey`

```rust
pub struct PropertyKey(String);
```

### Definition

Validated property name.

### Purpose

Prevents arbitrary unvalidated strings from spreading through the domain.

---

## `PropertyValue`

```rust
pub enum PropertyValue {
    Null,
    Bool(bool),
    String(String),
    Date(String),
    Number(i64),
    Float(f64),
    List(Vec<PropertyValue>),
    Object(Vec<PropertyEntry>),
}
```

### Definition

Typed property value.

### Purpose

Represents frontmatter values, inline-field values, and nested objects.

### Notes

`Object` is necessary for nested YAML/frontmatter-style structures.

# 5. Note Body

## `NoteBody`

```rust
pub struct NoteBody {
    pub headings: Vec<Heading>,
    pub sections: Vec<Section>,
    pub list_items: Vec<ListItem>,
    pub links: Vec<Link>,
    pub tags: Vec<Tag>,
}
```

### Definition

Semantic body of a note.

### Purpose

Stores queryable, addressable, or semantically meaningful note elements.

### Capabilities

- Heading lookup.
- Section hierarchy.
- List/task querying.
- Link extraction.

### Notes

`NoteBody` deliberately excludes parser-only markdown blocks such as paragraphs, code blocks, tables, HTML blocks, and thematic breaks.

# 6. Headings and Sections

## `Heading`

```rust
pub struct Heading {
    pub id: HeadingId,
    pub level: HeadingLevel,
    pub text: HeadingText,
    pub slug: HeadingSlug,
    pub span: SourceSpan,
}
```

### Definition

Semantic heading inside a note.

### Purpose

Supports outline navigation, section construction, and heading links.

### Capabilities

- Can be referenced by `Section`.
- Can be targeted by `LinkTarget::Heading`.
- Can be searched by slug/text/level.

---

## `HeadingLevel`

```rust
pub struct HeadingLevel(u8);
```

### Definition

Heading depth.

### Purpose

Represents levels such as `#`, `##`, `###`.

### Invariant

Usually valid only in range `1..=6`.

---

## `HeadingText`

```rust
pub struct HeadingText(String);
```

### Definition

Visible heading text.

---

## `HeadingSlug`

```rust
pub struct HeadingSlug(String);
```

### Definition

Normalized heading target.

### Purpose

Used for heading references and link resolution.

---

## `Section`

```rust
pub struct Section {
    pub id: SectionId,
    pub heading_id: Option<HeadingId>,
    pub level: SectionLevel,
    pub parent_id: Option<SectionId>,
    pub span: SourceSpan,
}
```

### Definition

Semantic range of a note, usually introduced by a heading.

### Purpose

Represents the note’s structural organization without becoming a nested aggregate.

### Capabilities

- Section hierarchy.
- Section-scoped queries by span.
- Outline construction.
- Folding/navigation.

### Notes

A section does not own child objects such as links, tags, or list items. Those can be derived by checking whether their `SourceSpan` falls within the section span.

---

## `SectionLevel`

```rust
pub struct SectionLevel(u8);
```

### Definition

Semantic depth of a section.

### Purpose

Usually corresponds to the heading level.

---

# 7. Lists and Tasks

## `ListItem`

```rust
pub struct ListItem {
```

# 8. Links and Tags

## `Link`

```rust
pub struct Link {
    pub id: LinkId,
    pub kind: LinkKind,
    pub role: LinkRole,
    pub target: LinkTarget,
    pub display_text: Option<String>,
    pub span: SourceSpan,
}
```

### Definition

A reference from this note to another target.

### Purpose

Models markdown links, wiki links, autolinks, reference links, and embeds.

### Capabilities

- Internal note links.
- External URL links.
- Heading references.
- Block references.
- Embed detection.

---

## `LinkKind`

```rust
pub enum LinkKind {
    Markdown,
    Wiki,
    Reference,
    Autolink,
}
```

### Definition

How the link was written.

### Purpose

Preserves source-level link style without confusing it with the target.

---

## `LinkRole`

```rust
pub enum LinkRole {
    Reference,
    Embed,
}
```

### Definition

What the link does.

### Purpose

Distinguishes normal references from embeds.

### Notes

Embeds are links with role `Embed`, not separate domain entities.

---

## `LinkTarget`

```rust
pub enum LinkTarget {
    ExternalUrl(String),
    Note(NotePath),

        note: Option<NotePath>,
        block_id: String,
    },
}
```

### Definition

The thing a link points to.

### Purpose

Keeps heading and block references as targets, not link kinds.

---

## `Tag`


### Definition

A tag occurrence in the note.

### Purpose

Represents tags as annotations/metadata, not links.

### Notes

## `TagValue`

```rust
pub struct TagValue(String);
```

### Definition

# 9. Borrowed Reference Helpers

These are optional. Add only when methods need both a specific object and the parent note.

Do not use `*View` here because `*View` is reserved for persisted DB read models.

## `SectionRef`

```rust
pub struct SectionRef<'a> {
    pub note: &'a Note,
    pub section: &'a Section,
}
```

### Definition

Borrowed reference to a section with access to the parent note.

### Purpose

Enables section-scoped semantic queries.

### Capabilities

```rust
impl<'a> SectionRef<'a> {
    pub fn heading(&self) -> Option<&'a Heading>;
    pub fn child_sections(&self) -> impl Iterator<Item = SectionRef<'a>>;
    pub fn list_items(&self) -> impl Iterator<Item = &'a ListItem>;
    pub fn links(&self) -> impl Iterator<Item = &'a Link>;
    pub fn tags(&self) -> impl Iterator<Item = &'a Tag>;
}
```

---

## `HeadingRef`

```rust
pub struct HeadingRef<'a> {
    pub note: &'a Note,
    pub heading: &'a Heading,
}
```

### Definition

Borrowed heading plus parent note context.

### Purpose

Useful when resolving the section introduced by a heading.

---

## `ListItemRef`

```rust
pub struct ListItemRef<'a> {
    pub note: &'a Note,
    pub item: &'a ListItem,
}
```

### Definition

Borrowed list item plus parent note context.

### Purpose

Enables parent/child traversal and task-specific behavior.

### Capabilities

```rust
impl<'a> ListItemRef<'a> {
    pub fn parent(&self) -> Option<ListItemRef<'a>>;
    pub fn children(&self) -> impl Iterator<Item = ListItemRef<'a>>;
    pub fn is_task(&self) -> bool;
    pub fn task_status(&self) -> Option<&'a TaskStatus>;
}
```

# 12. Suggested redb Storage Categories

## Aggregate cache

```text
note_by_id
note_by_path
note_fingerprint_by_path
```

Stores note identity, path, hash/fingerprint, and optionally serialized `Note`.

---

## Per-note views

```text
headings_by_note
sections_by_note
tasks_by_note
links_by_note
tags_by_note
properties_by_note
```

Used to retrieve semantic objects for one note.

---

## Cross-note indexes

```text
notes_by_tag
notes_by_property_key
links_by_target
backlinks_by_target
tasks_by_status
```

Used for vault-wide queries.

# 13. Naming Rules

## Domain

Use direct semantic names:

```text
Note
Frontmatter
NoteBody
Heading
Section
ListItem
Link
Tag
PropertySet
```

## Borrowed helpers

Use `*Ref` only when the type borrows both the parent note and a specific object:

```text
SectionRef
HeadingRef
ListItemRef
```

Avoid wrappers that only contain:

```rust
note: &Note
```

Prefer methods on `Note` instead.

## Database read models

Use `*View` exclusively for persisted database projections:

```text
TaskView
LinkView
TagView
PropertyView
HeadingView
SectionView
```

---

# 14. Final Layer Summary

| Layer | Components |
|---|---|
| Parser layer | `ParsedMarkdown`, `MarkdownBlock`, `MarkdownBlockKind` |
| Aggregate root | `Note` |
| Aggregate-owned semantic body | `Frontmatter`, `NoteBody` |
| Domain entities | `Heading`, `Section`, `ListItem`, `Link` |
| Domain value objects | `NotePath`, `SourceSpan`, `PropertySet`, `PropertyValue`, `Tag`, `HeadingText`, `HeadingSlug`, `TaskStatus` |
| Borrowed refs | `SectionRef`, `HeadingRef`, `ListItemRef` |
| Persisted DB views | `TaskView`, `LinkView`, `TagView`, `PropertyView`, `HeadingView`, `SectionView` |

---

# 15. Final Design Rule

Start with:

```text
methods on Note
```

Add:

```text
*Ref types
```

only when a method needs both a specific object and the parent note.

Persist:

```text
*View types
```

only when redb needs query-optimized data across notes.
