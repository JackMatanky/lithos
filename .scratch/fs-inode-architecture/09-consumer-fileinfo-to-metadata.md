### Category: enhancement

### Summary

Migrate all consumers from legacy `FileInfo` (flat struct in `fs/file.rs`) to the new unified `FileMetadata` (compositional struct in `fs/metadata.rs`) as part of the inode-based filesystem architecture unification.

### Current Behavior

The codebase uses **`FileInfo`** as the primary metadata carrier:

```rust
// fs/file.rs - LEGACY
pub struct FileInfo {
    created_at: Option<SystemTime>,
    modified_at: Option<SystemTime>,
    size: u64,
}

impl FileInfo {
    pub fn is_timestamp_match(&self, ...) -> bool { /* ... */ }
    pub fn is_size_match(&self, size: u64) -> bool { /* ... */ }
}
```

This struct is used in:
- **`FileEntry::info`** field (file system entry struct)
- **`SchemaVersion::info`** (schema snapshot metadata)
- **`PropertyBankVersion::info`** (property bank snapshot metadata)
- **`RawSchemaView::info`** and **`RawPropertyBankView::info`** (raw view containers)
- **`ConfigDiscovered::info`** (config discovery result)
- Trait methods: `Version::file_info()`, `Version::set_file_info()`, `VersionRead::file_info()`

**255 usage sites** across `fs/`, `schema/`, `config/`, `vault/`, and tests.

**Conversion Path**: `FileMetadata` → `FileInfo` via `From` impls (lines 155-175 of `fs/file.rs`) enables temporary compatibility.

### Desired Behavior

All consumers should use **`FileMetadata`** from `fs/metadata.rs`:

```rust
// fs/metadata.rs - TARGET
pub struct FileMetadata {
    times: FsTimes,
    size: u64,
    is_symlink: bool,
}

impl FileMetadata {
    pub fn times(&self) -> &FsTimes { &self.times }
    pub fn size(&self) -> u64 { self.size }
}

pub struct FsTimes {
    created_at: Option<SystemTime>,
    modified_at: Option<SystemTime>,
}

impl FsTimes {
    pub fn created_at(&self) -> Option<SystemTime> { self.created_at }
    pub fn modified_at(&self) -> Option<SystemTime> { self.modified_at }
    pub fn is_match(&self, other: &FsTimes) -> bool { /* ... */ }
}
```

**Key API Differences**:
1. **Constructor**: `FileInfo::new(created, modified, size)` → `FileMetadata::new(FsTimes::new(created, modified), size, false)`
2. **Timestamp Access**: `info.created_at()` → `metadata.times().created_at()` (composition, not shortcut)
3. **Timestamp Comparison**: `info.is_timestamp_match(c, m)` → `metadata.times().is_match(&other_times)` OR new method on `FileMetadata`
4. **Archived Access**: `ArchivedFileInfo` → `ArchivedFileMetadata` for zero-copy staleness checks

**Field Renames**:
- `FileEntry::info` → `FileEntry::metadata`
- `SchemaVersion::info` → `SchemaVersion::metadata`
- `PropertyBankVersion::info` → `PropertyBankVersion::metadata`
- `RawSchemaView::info` → `RawSchemaView::metadata`
- `RawPropertyBankView::info` → `RawPropertyBankView::metadata`
- `ConfigDiscovered::info` → `ConfigDiscovered::metadata`
- Trait methods: `file_info()` → `metadata()`, `set_file_info()` → `set_metadata()`

### Infrastructure Requirements (MUST BE COMPLETED FIRST)

**Phase 1a: Add Missing `FileMetadata` Staleness APIs** (in `fs/metadata.rs`)

The migration requires parity with `FileInfo`'s staleness check methods. Add:

```rust
impl FileMetadata {
    /// Compare metadata size.
    pub fn is_size_match(&self, size: u64) -> bool {
        self.size == size
    }

    /// Compare timestamps against external values.
    /// Delegates to FsTimes for timestamp matching.
    pub fn is_timestamp_match(
        &self,
        created_at: Option<SystemTime>,
        modified_at: Option<SystemTime>,
    ) -> bool {
        let other = FsTimes::new(created_at, modified_at);
        self.times.is_match(&other)
    }
}

impl ArchivedFileMetadata {
    /// Zero-copy timestamp comparison for archived metadata.
    pub fn is_timestamp_match(
        &self,
        created_at: Option<SystemTime>,
        modified_at: Option<SystemTime>,
    ) -> bool {
        self.times.is_timestamp_match(created_at, modified_at)
    }
}

impl ArchivedFsTimes {
    /// Zero-copy timestamp comparison for archived times.
    pub fn is_timestamp_match(
        &self,
        created_at: Option<SystemTime>,
        modified_at: Option<SystemTime>,
    ) -> bool {
        // Convert SystemTime to Unix seconds for comparison with archived data
        let created_match = match (self.created_at.as_ref(), created_at) {
            (Some(archived), Some(sys)) => {
                let unix_secs = sys
                    .duration_since(UNIX_EPOCH)
                    .ok()
                    .and_then(|d| i64::try_from(d.as_secs()).ok());
                unix_secs == Some(archived.as_secs())
            }
            (None, None) => true,
            _ => false,
        };

        let modified_match = match (self.modified_at.as_ref(), modified_at) {
            (Some(archived), Some(sys)) => {
                let unix_secs = sys
                    .duration_since(UNIX_EPOCH)
                    .ok()
                    .and_then(|d| i64::try_from(d.as_secs()).ok());
                unix_secs == Some(archived.as_secs())
            }
            (None, None) => true,
            _ => false,
        };

        created_match && modified_match
    }
}
```

### Key Constraints

1. **Favor Composition Over Shortcuts** (Rust Best Practice 1.1):
   - DO: `metadata.times().created_at()`
   - DON'T: Add `created_at()` method to `FileMetadata` that forwards to `times.created_at()`
   - Rationale: Avoid unjustified API duplication. The extra chaining `.times()` makes the compositional structure explicit.

2. **Delay Clones** (Rust Best Practice 3.2):
   - Prefer `&FileMetadata` over cloning until ownership transfer is required.
   - When converting from `std::fs::Metadata`, construct `FileMetadata` directly (already done via `From` impl).

3. **Test Through Public Interfaces** (TDD Philosophy):
   - Tests verify behavior via public methods, not internal fields.
   - Existing tests like `schema::views::snapshots::tests::schema_version::new_extracts_metadata_correctly` should survive the migration with minimal changes (only type and field renames).

4. **No Temporary Compatibility Aliases**:
   - Delete `FileInfo` and its `From<FileMetadata>` conversions immediately after all consumers are migrated.
   - No `type FileInfo = FileMetadata` alias layer.
