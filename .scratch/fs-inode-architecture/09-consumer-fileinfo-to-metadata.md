## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Replace legacy `FileInfo` with unified `FileMetadata` across all system contexts.

**Current behavior:**
The codebase currently maintains two overlapping metadata types for files:
1. `FileInfo` (in `fs/file.rs`): A legacy, flattened structure used primarily for staleness detection in the `schema` context and by `FileEntry`.
2. `FileMetadata` (in `fs/metadata.rs`): A newer, structured type that uses `FsTimes` for nested timestamps and includes `is_symlink` status.

`FsFile` already uses `FileMetadata`, but many other consumers (especially in the `schema` context like `SchemaVersion` and `PropertyBankVersion`) still depend on `FileInfo`.

**Desired behavior:**
`FileInfo` should be completely removed from the codebase. All consumers should be updated to use `FileMetadata` directly. This includes:
- Updating `FileEntry` to use `FileMetadata`.
- Updating `SchemaVersion` and `PropertyBankVersion` in the `schema` context.
- Updating `FsReader` and `DirScanner` usages.
- Adjusting call sites to handle the nested `times` field (e.g., `info.created_at()` -> `metadata.times().created_at()`).
- Replacing `FileInfo::is_timestamp_match` with `FsTimes::is_match`.
- Replacing `FileInfo::is_size_match` with direct size comparison.

**Key interfaces:**
- `FileInfo` — to be deleted.
- `FileMetadata` — the target replacement.
- `FsEntry` / `FsFile` — current users of `FileMetadata`.
- `SchemaVersion` / `PropertyBankVersion` — major consumers that need migration.
- `FsReader` — interface that returns file metadata.

**Acceptance criteria:**
- [ ] `FileInfo` struct and its implementation removed from `fs/file.rs`.
- [ ] `FileEntry` updated to use `FileMetadata`.
- [ ] All `schema` context versioning types (`SchemaVersion`, `PropertyBankVersion`) use `FileMetadata`.
- [ ] All occurrences of `FileInfo` replaced with `FileMetadata` (no aliases).
- [ ] `mise run verify` passes (fmt, lint, tests).

**Out of scope:**
- Redesigning `FileMetadata` or `FsTimes` structures.
- Migrating existing on-disk binary data (persistence break is acceptable in this phase).
