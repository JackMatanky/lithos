# Story 6.3: TemplateEngine Function Provider Pattern

## Status

ready-for-dev

## Story

**As a** developer,
**I want** template functions extracted into provider objects,
**so that** the TemplateEngine becomes extensible and template functions are testable in isolation.

## Context

**Current Problem:**
TemplateEngine is a 584-line service with:
- Template rendering logic
- Template function factories (makeQueryFunc, makeLookupFunc, makeFileClassFunc)
- Event publishing mixed with template logic
- Template caching
- Template function registration

Template functions are tightly coupled to TemplateEngine, making it hard to:
- Test template functions independently
- Add new template functions
- Understand template function behavior

**Refactoring Goal:**
Extract template functions into provider objects using Strategy Pattern where:
1. Each function group has its own provider
2. Providers are injected via DI
3. Providers can be tested independently
4. New providers can be added without modifying TemplateEngine

**Target Architecture:**
```
TemplateEngine (200 lines) - Core rendering
├── TemplateFunctionRegistry (100 lines) - Function registration
│   ├── LookupFunctionProvider (80 lines) - lookup() function
│   ├── QueryFunctionProvider (80 lines) - query() function
│   └── FileClassFunctionProvider (80 lines) - fileClass() function
└── TemplateCache (50 lines) - Template caching
```

## Dev Notes

### Provider Pattern Benefits

**Before (Tightly Coupled):**
```go
// TemplateEngine has makeQueryFunc, makeLookupFunc, makeFileClassFunc
// All mixed with rendering logic
```

**After (Provider Pattern):**
```go
// TemplateEngine delegates to providers
type FunctionProvider interface {
    Name() string
    Function(ctx context.Context) any
}

// Easy to add new providers without modifying TemplateEngine
```

### Component Responsibilities

**TemplateFunctionRegistry:** Function registration and retrieval
**LookupFunctionProvider:** lookup() function logic + events
**QueryFunctionProvider:** query() function logic + events
**FileClassFunctionProvider:** fileClass() function logic + events
**TemplateCache:** Template caching only
**TemplateEngine:** Template rendering only

### Migration Path

1. Create TemplateFunctionRegistry first
2. Extract LookupFunctionProvider (simplest)
3. Extract FileClassFunctionProvider
4. Extract QueryFunctionProvider (most complex)
5. Extract TemplateCache
6. Refactor TemplateEngine to use registry
