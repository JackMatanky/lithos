# Story 6.4: QueryService Observability Extraction

## Status

ready-for-dev

## Story

**As a** developer,
**I want** observability concerns extracted from QueryService,
**so that** the service focuses on query execution while monitoring is handled separately.

## Context

**Current Problem:**
QueryService is a 567-line service mixing:
- Hybrid storage routing (BoltDB + SQLite)
- Query execution (path, basename, alias, fileClass, frontmatter)
- Event subscription (VaultIndexingCompleteEvent)
- Failure tracking (BackendFailureTracker)
- Staleness observation (StalenessObserver)
- Performance logging

Some observability components are already extracted (BackendFailureTracker, StalenessObserver), but they're not properly coordinated.

**Refactoring Goal:**
Complete the observability extraction by:
1. Creating QueryEventSubscriber to handle all event subscriptions
2. Creating BackendHealthMonitor to coordinate health monitoring
3. Reducing QueryService to pure query logic

**Target Architecture:**
```
QueryService (150 lines) - Core query execution
├── HybridStorageRouter (already extracted ✅)
├── QueryEventSubscriber (50 lines) - Event subscription coordination
└── BackendHealthMonitor (100 lines) - Health monitoring coordination
    ├── BackendFailureTracker (already extracted ✅)
    └── StalenessObserver (already extracted ✅)
```

### Migration Path

5. Remove observability logic from QueryService
