# QA Fixes: Story 3.20 BoltDB Hot Cache Adapter

## Status: Done

### 1. Incomplete Delete Implementation (AC 3, AC 6)
- **Location**: `internal/adapters/spi/cache/boltdb/writer.go`
- **Issue**: The `Delete` method contains a `TODO: Implement full index cleanup` and explicitly states "For now, we just delete from primary path bucket."
- **Requirement Violation**: AC 3 requires maintaining all indices transactionally. Task 6.4 "Implement Delete() with transactional secondary index cleanup" was marked complete but is not.
- **Impact**: Secondary indices (`byBasename`, `byAlias`, `byFileClass`, `byFolder`) will retain references to deleted notes. Over time, this causes index bloat and potentially incorrect query results if paths are reused or if the reader doesn't filter out missing primary keys efficiently.

### 2. Missing Test Coverage for Index Cleanup
- **Location**: `internal/adapters/spi/cache/boltdb/writer_test.go`
- **Issue**: `TestBoltDBCacheWriteAdapter_Delete` only asserts that the note is removed from `BucketNotes`. It does not verify that the corresponding entries are removed from `BucketIndices`.
- **Remediation**: Update the test to assert that secondary indices are also cleared.

### 3. Missing Transaction Rollback Tests (AC 6)
- **Location**: `internal/adapters/spi/cache/boltdb/writer_test.go`
- **Issue**: AC 6 requires "rollback paths are fully tested". No tests currently simulate a failure during a multi-step transaction (e.g., failing to write to a secondary index) to verify rollback behavior.

## Recommendations

1.  **Implement Index Cleanup**: Update `Delete` in `writer.go` to:
    - Read the note first (to get basename, aliases, etc.).
    - Remove entries from all secondary index buckets (`byBasename`, `byAlias`, etc.).
    - Delete from primary bucket.
    - Do this all in one transaction.
2.  **Enhance Tests**: Add test cases for index cleanup and transaction rollback.
