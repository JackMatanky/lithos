# Story 4.9: Vault Package Idiomatic Go Simplification

## Status: pending

## Story

As a developer,
I want to simplify the vault package using idiomatic Go patterns by consolidating the 5 separate services into a clean VaultIndexer with focused helpers, while preserving all current capabilities and integrating Story 4.8 improvements,
So that the code follows Go conventions, reduces complexity from ~2100 lines to ~1200 lines, and maintains all functionality with better maintainability.

## Context

The vault package currently has 5 separate services with overlapping responsibilities and non-idiomatic Go patterns:

**Current Structure (Over-engineered):**
- `VaultIndexer` (938 lines) - God object with 10+ dependencies
- `CachingService` (107 lines) - Cache writing
- `MarkdownProcessingService` (91 lines) - Markdown parsing
- `NoteValidationService` (94 lines) - Frontmatter validation
- `DataProcessingOrchestrator` (141 lines) - Event coordination

**Problems:**
- Service suffix everywhere (non-idiomatic)
- Massive dependency overlap
- Unnecessary abstractions
- Complex interactions between tiny services

**Idiomatic Go Solution:**
- `VaultIndexer` - Main struct with all orchestration + processing methods
- `CacheWriter` - Simple cache writing helper
- `Processor` - Consolidated markdown parsing + validation
- `events.go` - Event publishing helpers (Story 4.8 pattern)

**All Current Capabilities Preserved:**
- ✅ Full vault scanning and indexing (Build/Refresh)
- ✅ Individual file processing (markdown → validation → cache)
- ✅ Event-driven processing pipeline
- ✅ Cache writing with ParallelWriter transactions
- ✅ Schema loading and validation
- ✅ Deletion reconciliation and cache validation
- ✅ Statistics collection and monitoring
- ✅ Event handling and publishing

### Event Helpers (events.go)

Following Story 4.8 pattern from `template/events.go`:

```go
package vault

import (
    "context"
    "github.com/JackMatanky/lithos/internal/app/events"
    "github.com/JackMatanky/lithos/internal/domain"
    "github.com/rs/zerolog"
)

func publishNoteParsed(ctx context.Context, bus events.EventBus, log zerolog.Logger, note domain.Note) {
    if bus == nil {
        return
    }
    event := events.MustNewNoteParsedEvent(note, time.Now())
    events.PublishSync(ctx, bus, log, event)
}

func publishFrontmatterValidated(ctx context.Context, bus events.EventBus, log zerolog.Logger, note domain.Note, isValid bool, errors []string) {
    if bus == nil {
        return
    }
    event := domain.MustNewFrontmatterValidatedEvent(note, note.FileClass(), isValid, errors, time.Now())
    events.PublishSync(ctx, bus, log, event)
}

func publishNoteIndexed(ctx context.Context, bus events.EventBus, log zerolog.Logger, note domain.Note) {
    if bus == nil {
        return
    }
    event, err := domain.NewNoteIndexedEvent(note, time.Now())
    if err != nil {
        log.Warn().Err(err).Str("path", note.Path).Msg("failed to create note indexed event")
        return
    }
    if publishErr := events.PublishSync(ctx, bus, event); publishErr != nil {
        log.Warn().Err(publishErr).Str("path", note.Path).Msg("failed to publish note indexed event")
    }
}
```

## Rationale

This refactoring achieves the perfect balance:

**Simplification:** Consolidates 5 services into 1 main struct + 2 simple helpers, following Go's preference for clarity over unnecessary abstraction.

**Functionality:** Preserves 100% of current capabilities while integrating Story 4.8 improvements.

**Idiomatic Go:** Uses simple names, clear file structure, and Go conventions throughout.

**Maintainability:** Single `VaultIndexer` with methods is much easier to understand and modify than 5 separate services with complex interactions.

The result is a vault package that does everything the current version does, but with ~43% less code and much better organization.
