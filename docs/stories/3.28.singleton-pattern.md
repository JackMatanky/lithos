### Architecture Patterns

**Singleton Pattern:**
Config and PropertyBank are global shared resources requiring single instance:
- **sync.Once:** Thread-safe initialization guarantee
- **Instance() accessor:** Centralized access to singleton
- **SetInstanceForTesting():** Test isolation without global state pollution

**Dependency Injection:**
Singletons integrate cleanly with DI:
```go
// In registry
func RegisterConfig(container *Container) {
    container.Provide(config.Instance)
}

// Services receive injected singleton
func NewVaultIndexer(cfg *config.Config) *VaultIndexer
```

**Test Isolation:**
SetInstanceForTesting() enables:
- Independent test execution
- Custom config per test
- Cleanup after tests

### Implementation Notes

**Phase 1: Config Singleton**
Implement Config.Instance() with sync.Once and SetInstanceForTesting().

**Phase 2: PropertyBank Singleton**
Implement PropertyBank.Instance() with sync.Once and SetInstanceForTesting().

**Phase 3: Usage Migration**
Find and update all direct Config/PropertyBank creation to use Instance().

**Phase 4: DI Integration**
Update DI registry to provide singletons instead of creating instances.

### Risks and Mitigations

**MEDIUM RISK: Global state testing challenges**
- **Impact:** Tests may affect each other through shared singleton
- **Mitigation:** SetInstanceForTesting() for test isolation; reset in test cleanup
- **Validation:** Parallel test execution to detect coupling

**LOW RISK: Initialization order dependencies**
- **Impact:** Singleton initialization may depend on other singletons
- **Mitigation:** Document initialization order; lazy initialization with sync.Once
- **Validation:** Unit tests for initialization edge cases
