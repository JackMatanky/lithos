### Architecture Patterns

**Schema-Driven View Pattern:**
SQLite views are generated dynamically from PropertyBank schemas. Each schema gets a dedicated view with:
- Typed columns extracted from JSON frontmatter
- fileClass filtering in WHERE clause
- Indices on commonly queried fields

This enables O(1) indexed queries instead of O(n) JSON scanning.

**Hybrid Storage Strategy:**
- **BoltDB (Hot):** Fast path lookups (ByPath, ByBasename, ByAlias) - Story 3.19
- **SQLite (Deep):** Complex frontmatter queries (ByFileClass, ByFrontmatterField) - This story
- **Query Routing:** Hot queries → BoltDB, complex queries → SQLite (Story 3.22)

**PropertySpec → SQL Type Mapping:**
```
StringSpec → TEXT
IntegerSpec → INTEGER
BooleanSpec → INTEGER (0/1)
ArraySpec → TEXT (JSON array)
ObjectSpec → TEXT (JSON object)
FileSpec → TEXT (path string)
```

**View Migration Strategy:**
- Schema changes trigger view DROP + CREATE
- Version tracking in metadata table
- Graceful degradation if view missing (fallback to JSON queries)

### Schema-Driven View Example

**Input Schema (PropertyBank):**
```json
{
  "name": "contact",
  "properties": [
    {"name": "name", "type": "string", "required": true},
    {"name": "email", "type": "string"},
    {"name": "phone", "type": "string"},
    {"name": "status", "type": "string", "enum": ["active", "inactive"]}
  ]
}
```

**Generated View:**
```sql
CREATE VIEW v_contact_notes AS
SELECT
    id,
    path,
    json_extract(frontmatter, '$.name') AS name,
    json_extract(frontmatter, '$.email') AS email,
    json_extract(frontmatter, '$.phone') AS phone,
    json_extract(frontmatter, '$.status') AS status,
    mod_time,
    size
FROM notes
WHERE json_extract(frontmatter, '$.fileClass') = 'contact';

CREATE INDEX idx_contact_status ON v_contact_notes(status);
CREATE INDEX idx_contact_name ON v_contact_notes(name);
```

**Query Usage:**
```go
// O(1) indexed query using view
SELECT * FROM v_contact_notes WHERE status = 'active' ORDER BY name;

// vs O(n) JSON scan without view
SELECT * FROM notes WHERE json_extract(frontmatter, '$.status') = 'active';
```

### Risks and Mitigations

**HIGH RISK: View generation complexity**
- **Impact:** PropertySpec → SQL type mapping may have edge cases
- **Mitigation:** Start with simple types (string, integer); incremental expansion
- **Validation:** Comprehensive unit tests for type mapping

**MEDIUM RISK: Schema changes require view migration**
- **Impact:** View must be recreated when schema changes
- **Mitigation:** Document regeneration procedure; version views
- **Validation:** Integration tests for schema change workflow

**LOW RISK: Query performance on large datasets**
- **Impact:** SQLite may not meet < 50ms target for 1000+ notes
- **Mitigation:** Proper indexing; query optimization; benchmark early
- **Validation:** Performance tests with realistic dataset sizes
