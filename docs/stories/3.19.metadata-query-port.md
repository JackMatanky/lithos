# Story 3.19: MetadataQueryPort - Index-Based Query Interface

## Status: Draft

## Story

**As a** system architect,
**I want** a dedicated MetadataQueryPort interface for index-based note queries (ByBasename, ByAlias, ByFileClass),
**so that** we enable efficient metadata lookups with proper port/adapter separation and support the hybrid storage architecture.

## Acceptance Criteria

**New Port Definition**:
1. ✅ Create `/internal/ports/spi/metadata_query.go`:
   ```go
   type MetadataQueryPort interface {
       // ByBasename finds notes by filename without extension
       // Returns all notes with matching basename (handles duplicates)
       ByBasename(ctx context.Context, basename string) ([]domain.Note, error)

       // ByAlias finds notes by frontmatter alias values
       // Returns all notes containing the alias in aliases array
       ByAlias(ctx context.Context, alias string) ([]domain.Note, error)

       // ByFileClass finds notes by schema fileClass value
       // Returns all notes with matching fileClass frontmatter field
       ByFileClass(ctx context.Context, fileClass string) ([]domain.Note, error)
   }
   ```

**Port Documentation**:
2. ✅ Update `docs/architecture/components.md` with MetadataQueryPort specification
3. ✅ Document query semantics and performance expectations
4. ✅ Document relationship to CacheReaderPort (complementary interfaces)

**Mock Implementation**:

### Architecture Patterns

**Port/Adapter Pattern:**
- MetadataQueryPort (SPI): Contract defined by domain query needs
- Future adapters: BoltDBReaderAdapter, SQLiteReaderAdapter will implement this interface
- Clear separation: Port defines WHAT, adapters define HOW

**Interface Segregation:**
MetadataQueryPort focuses specifically on index-based metadata queries:
- **NOT included**: Full-text search (different interface)
- **NOT included**: Complex frontmatter queries (SQLiteQueryPort)
- **Included**: Fast index lookups by basename, alias, fileClass

**Complementary Interfaces:**
- **CacheReaderPort**: Basic cache operations (Read by path, List all)
- **MetadataQueryPort**: Index-based queries (ByBasename, ByAlias, ByFileClass)
- **QueryService**: Orchestrates queries across multiple ports

**Query Routing Strategy:**
```go
// QueryService routes queries to appropriate ports
func (s *QueryService) FindByBasename(basename string) ([]Note, error) {
    // Route to MetadataQueryPort for fast index lookup
    return s.metadataQuery.ByBasename(ctx, basename)
}

func (s *QueryService) ComplexFrontmatterQuery(criteria map[string]any) ([]Note, error) {
    // Route to SQLiteQueryPort for complex queries (future story)
    return s.sqliteQuery.QueryFrontmatter(ctx, criteria)
}
```

### Interface Design Principles

**Method Naming Consistency:**
- `ByBasename()` - Consistent with domain concepts (Note.Basename())
- `ByAlias()` - Matches frontmatter field name
- `ByFileClass()` - Matches schema selection mechanism

**Return Type Consistency:**
- All methods return `([]domain.Note, error)`
- Empty slice for no results (not nil)
- Context-aware cancellation support

**Error Handling:**
- ErrNotFound NOT returned for empty results (return empty slice)
- Context cancellation propagated properly
- Infrastructure errors wrapped with meaningful context
