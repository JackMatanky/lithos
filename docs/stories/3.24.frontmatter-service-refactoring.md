### Architecture Patterns

**Hexagonal Architecture (Ports & Adapters):**
FrontmatterService is in the domain layer and must remain pure. It now depends on MarkdownParserPort (SPI port) instead of goldmark directly. This maintains clean architectural separation:
- **Port:** MarkdownParserPort defines parsing interface (SPI)
- **Adapter:** GoldmarkAdapter implements parsing (adapter layer)
- **Service:** FrontmatterService uses port for validation (domain layer)

**Dependency Inversion:**
High-level FrontmatterService depends on abstraction (MarkdownParserPort), not concrete implementation (goldmark). This enables:
- **Testability:** Mock parser for pure domain tests
- **Flexibility:** Swap parsers without changing service
- **Domain Purity:** No external library dependencies in domain

**Validation Layer Separation:**
Following Story 3.26 guidance:
- **Syntactic Validation:** Adapter layer (MarkdownParserPort) validates YAML syntax
- **Semantic Validation:** Domain layer (FrontmatterService.IsSchemaCompliant) validates schema compliance

### Implementation Notes

**Phase 1: Constructor Refactoring**
Start by injecting MarkdownParserPort into FrontmatterService. This breaks goldmark dependency without changing validation logic.

**Phase 2: Validation Method Renaming**
Rename Validate() to IsSchemaCompliant() to clarify semantic validation responsibility. Update all call sites.

**Phase 3: Domain Purity**
Remove all goldmark imports. Use mock MarkdownParserPort in unit tests to achieve pure domain testing.

**Phase 4: Integration Testing**
Add integration tests with real GoldmarkAdapter to verify end-to-end flow.

### Risks and Mitigations

**MEDIUM RISK: Breaking changes to FrontmatterService consumers**
- **Impact:** All services calling Validate() must update to IsSchemaCompliant()
- **Mitigation:** Update all call sites in same story; comprehensive integration tests
- **Validation:** Run full test suite after renaming

**LOW RISK: Mock parser may not match real parser behavior**
- **Impact:** Unit tests pass but integration tests fail
- **Mitigation:** Comprehensive integration tests with real GoldmarkAdapter
- **Validation:** Integration test coverage for all validation paths
