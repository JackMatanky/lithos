### Architecture Patterns

**Schema-Driven View Pattern:**
SQLite views are generated dynamically from PropertyBank schemas. Each schema gets a dedicated view with:
- Typed columns extracted from JSON frontmatter
- fileClass filtering in WHERE clause
- Indices on commonly queried fields

This enables O(1) indexed queries instead of O(n) JSON scanning.

**Hybrid Storage Strategy:**
- **BoltDB (Hot):** Fast path lookups (PathQuery, BasenameQuery, AliasQuery) - Story 3.20
- **SQLite (Deep):** Complex frontmatter queries (FileClassQuery, FrontmatterFieldQuery) - This story
- **Query Routing:** Hot queries → BoltDB, complex queries → SQLite (Story 3.22)

**Cache Staleness Pattern:**
SQLite tracks both file modification time and cache index time for each note:
- **modified_at:** File's last modification timestamp (from VaultFile)
- **indexed_time:** When the note was cached
- **Staleness Query:** `SELECT path FROM notes WHERE modified_at > indexed_time`
- **GetStaleNotes():** Returns list of paths needing reindex
- **IsStale(path):** Single-note staleness check for incremental updates

**PropertySpec → SQL Type Mapping:**
```
StringSpec → TEXT
IntegerSpec → INTEGER
BooleanSpec → INTEGER (0/1)
ArraySpec → TEXT (JSON array)
ObjectSpec → TEXT (JSON object)
FileSpec → TEXT (path string)
```

**View Migration Strategy:**
- Schema changes trigger view DROP + CREATE
- Version tracking in metadata table
- Graceful degradation if view missing (fallback to JSON queries)

### Schema-Driven View Example

**Input Schema (PropertyBank):**
```json
{
  "name": "contact",
  "properties": [
    {"name": "name", "type": "string", "required": true},
    {"name": "email", "type": "string"},
    {"name": "phone", "type": "string"},
    {"name": "status", "type": "string", "enum": ["active", "inactive"]}
  ]
}
```

**Generated View:**
```sql
CREATE VIEW v_contact_notes AS
SELECT
    path,
    json_extract(frontmatter, '$.name') AS name,
    json_extract(frontmatter, '$.email') AS email,
    json_extract(frontmatter, '$.phone') AS phone,
    json_extract(frontmatter, '$.status') AS status,
    modified_at,
    indexed_time,
    size
FROM notes
WHERE json_extract(frontmatter, '$.fileClass') = 'contact';

CREATE INDEX idx_contact_status ON v_contact_notes(status);
CREATE INDEX idx_contact_name ON v_contact_notes(name);

-- Query for stale notes in this view
-- SELECT path FROM v_contact_notes WHERE modified_at > indexed_time;
```

**Query Usage:**
```go
// O(1) indexed query using view
SELECT * FROM v_contact_notes WHERE status = 'active' ORDER BY name;

// vs O(n) JSON scan without view
SELECT * FROM notes WHERE json_extract(frontmatter, '$.status') = 'active';
```

**MEDIUM RISK: Schema changes require view migration**

- **Mitigation:** Document regeneration procedure; version views
- **Validation:** Integration tests for schema change workflow

**LOW RISK: Query performance on large datasets**
- **Impact:** SQLite may not meet < 50ms target for 1000+ notes
- **Mitigation:** Proper indexing; query optimization; benchmark early

### Findings

1. **SchemaViewMigrator never runs with schemas** – `Storage()` always calls `initStorage` with `nil`, so `SchemaViewMigrator.EnsureViews` returns early and no views/indexes get created (AC 9-10). FileClass/Frontmatter queries therefore fall back to `json_extract` scans and fail the O(1) requirement (`cmd/lithos/main.go:80-86`, `internal/adapters/spi/cache/sqlite/view_migrator.go:51-57`).
2. **Staleness metadata ignores filesystem timestamps** – Vault indexing never propagates `dto.VaultFile.ModifiedAt()` or size into the Note, so the SQLite writer synthesizes `modified_at` from `time.Now()` (`internal/app/vault/indexer.go:662-685`, `internal/adapters/spi/cache/sqlite/writer.go:118-166`, `internal/adapters/spi/cache/helper.go:66-81`). As a result `modified_at` and `indexed_time` are always equal and `IsStale`/`GetStaleNotes` can never surface files that changed after indexing (AC 11-12).
3. **SQLite reader is not wired anywhere** – `storageResources` expose only the Bolt DB reader/writer, and there is no production instantiation of `NewSQLiteReaderAdapter`, so MetadataQueryPort plus schema views are unreachable in CLI flows (AC 14-17; `cmd/lithos/main.go:24-279`).
