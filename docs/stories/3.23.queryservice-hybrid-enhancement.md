# Story 3.23: QueryService Hybrid Storage Enhancement

## Status: Draft

## Story

**As a** system architect,
**I want** QueryService refactored to support hybrid BoltDB+SQLite query routing and CQRS compliance,
**so that** we fix architectural violations and enable production-grade query performance with proper command/query separation.

## Acceptance Criteria

**Hybrid Storage Support**:
1. ✅ QueryService constructor accepts both readers:
   ```go
   func NewQueryService(
       boltReader   spi.CacheReaderPort,
       sqliteReader spi.CacheReaderPort,  // Also implements MetadataQueryPort
       config       domain.Config,
       log          zerolog.Logger,
   ) *QueryService
   ```

**Query Routing Strategy**:
2. ✅ Hot path (BoltDB): `ByPath()`, `ByBasename()`, `ByAlias()` → sub-millisecond
3. ✅ Deep path (SQLite): `ByFrontmatterField()`, complex queries → use MetadataQueryPort
4. ✅ Merger logic: Combine results from both stores with consistency validation
5. ✅ Consistency check: Verify BoltDB and SQLite ModifiedAt match before returning

**Cache Staleness Detection**:
6. ✅ Staleness check on query:
   - QueryService checks cache staleness before returning results
   - Uses IndexTime comparison: if file.ModifiedAt() > cached.IndexTime → cache is stale
   - Logs warning when stale cache entry detected
   - (Optional) Triggers background reindex for stale entries

**CQRS Compliance Fix**:
7. ✅ Remove `RefreshFromCache()` from QueryService (write operation in query service)
8. ✅ Index rebuilding remains in `VaultIndexer` (command side)
9. ✅ QueryService is now **read-only** (true CQRS query side)

**Incremental Refresh Fix**:
10. ✅ Fix "ModifiedAt filtering broken" (lines 464-467 in service.go)
11. ✅ Implement staleness detection using SQLite: `SELECT * FROM notes WHERE modified_at > ?`
12. ✅ VaultIndexer.Refresh(since time.Time) loads only modified notes

**Testing**:
13. ✅ Unit tests: Query routing (hot vs deep), merger logic
14. ✅ Integration test: Index 100 notes, modify 5, RefreshIncremental loads only 5
15. ✅ Performance test: Hot path < 1ms, deep path < 50ms
16. ✅ Consistency test: BoltDB/SQLite mismatch detection

### Architecture Patterns

**Query Routing Strategy:**
```
User Query
    ↓
QueryService (Router)
    ├─ Hot Path → BoltDB (< 1ms)
    │   ├─ ByPath()
    │   ├─ ByBasename()
    │   └─ ByAlias()
    │
    └─ Deep Path → SQLite (< 50ms)
        ├─ ByFrontmatterField()
        ├─ FileClassQuery()
        └─ Complex queries using schema views
```

**CQRS Separation:**
- **Read Side (QueryService):** Read-only, no write operations
- **Command Side (VaultIndexer):** Handles index rebuilding, cache updates
- **Proper Separation:** Fixes architectural violation where QueryService had write operations

**Cache Staleness Detection:**
QueryService checks cache freshness before returning results:
- BoltDB/SQLite store IndexTime (when note was cached)
- QueryService compares file.ModifiedAt() vs cached.IndexTime
- If file.ModifiedAt > cached.IndexTime → cache is stale
- Stale detection logged as warning
- (Optional) Background reindex triggered for stale entries
