# Story 3.17: VaultFile DTO Redesign with Layered Architecture

## Status: Draft

## Story

**As a** system architect,
**I want** VaultFile DTO redesigned using layered architecture with base DTO, content separation, and storage-specific DTOs,
**so that** we eliminate duplication, enable vault-relative paths, and support hybrid BoltDB+SQLite storage efficiently.

## Acceptance Criteria

**Layer 1 - Base DTO** (AI-1.1 + AI-1.2):
1. ✅ Refactor `VaultFile` struct:
   ```go
   type VaultFile struct {
       Path    string      // Vault-relative: "notes/meeting.md"
       Info    fs.FileInfo // Delegate to stdlib (ModTime, Size, Mode, IsDir)
       Content []byte      // Loaded on-demand
   }
   ```
2. ✅ Add computed methods: `Basename()`, `Folder()`, `Ext()`, `ModTime()`, `Size()`
3. ✅ Remove duplicated fields: Basename, Folder, Ext, ModTime, Size, MimeType
4. ✅ Path normalization helper: `NormalizePath(absPath, vaultRoot string) (string, error)` using filepath.ToSlash
5. ✅ Helper: `AbsolutePath(vaultRoot string) string` for I/O operations

**Layer 2 - Content Separation** (AI-2.2):
6. ✅ Create `VaultFileMeta` struct (metadata only - NO Content):
   ```go
   type VaultFileMeta struct {
       Path string
       Info fs.FileInfo
   }
   ```
7. ✅ Create `VaultFileWithContent` struct (metadata + content):
   ```go
   type VaultFileWithContent struct {
       VaultFileMeta
       Content []byte
   }
   ```
8. ✅ Update VaultScannerPort methods:
   - `ScanAll(ctx) ([]VaultFileMeta, error)` - fast metadata scan
   - `ScanWithContent(ctx) ([]VaultFileWithContent, error)` - when content needed

**Layer 3 - Storage-Specific DTOs** (Entity Review Phase 3):
9. ✅ Create `BoltDBMetadata` (hot cache - minimal):
   ```go
   type BoltDBMetadata struct {
       Path      string
       Basename  string
       Aliases   []string
       FileClass string
       ModTime   time.Time
   }
   ```
10. ✅ Create `SQLiteMetadata` (deep storage - complete):
    ```go
    type SQLiteMetadata struct {
        Path        string
        Frontmatter map[string]any
        ModTime     time.Time
        Size        int64
    }
    ```
11. ✅ Conversion functions: `ToBoltDBMetadata()`, `ToSQLiteMetadata()`

**Cross-Platform Paths** (Gap 7.1):
12. ✅ All path storage uses forward slashes (filepath.ToSlash)
13. ✅ I/O operations convert to OS-specific paths (filepath.FromSlash)

**Testing**:
14. ✅ Unit tests: fs.FileInfo delegation, computed methods, path normalization
15. ✅ Cross-platform tests: Windows/Linux/Mac path compatibility
16. ✅ Memory tests: VaultFileMeta vs VaultFileWithContent memory usage

### Architecture Patterns

**Layered DTO Design:**
- Layer 1 (Base): VaultFile with fs.FileInfo delegation - eliminates duplication
- Layer 2 (Content Separation): VaultFileMeta vs VaultFileWithContent - memory optimization
- Layer 3 (Storage-Specific): BoltDBMetadata (hot) vs SQLiteMetadata (deep) - hybrid storage support

**Vault-Relative Paths:**
All internal paths use vault-relative format ("notes/meeting.md") with forward slashes for consistency. Conversion to absolute OS-specific paths happens only at I/O boundaries (adapter layer).

**fs.FileInfo Delegation:**
VaultFile embeds fs.FileInfo to delegate ModTime, Size, Mode, IsDir directly to stdlib. Computed methods (Basename, Folder, Ext) cache results to avoid repeated string operations.

**Content Separation Strategy:**
- VaultFileMeta: Fast metadata-only scans for file discovery
- VaultFileWithContent: Full content loading when parsing needed
- Memory savings: Skip loading binary files, large files during metadata scans

### Implementation Notes

**Phase 1: Base DTO Refactoring**
Start by refactoring VaultFile to use fs.FileInfo. This is the foundation - all other layers depend on it.

**Phase 2: Content Separation**
Create VaultFileMeta and VaultFileWithContent. Update VaultScannerPort with new methods. This enables memory optimization.

**Phase 3: Storage-Specific DTOs**
Define BoltDBMetadata and SQLiteMetadata. These will be used in Stories 3.19-3.20 for hybrid storage.

**Phase 4: Path Normalization**
Implement cross-platform path handling using filepath.ToSlash/FromSlash. Critical for Windows compatibility.

**Phase 5: Integration**
Update all VaultFile consumers to use new structure. Comprehensive testing across all layers.
