### Architecture Patterns

**Event-Driven Architecture:**
Services communicate via domain events instead of direct method calls. This reduces coupling and enables:
- **Loose Coupling:** Services don't know about each other, only events
- **Scalability:** Easy to add new subscribers without modifying publishers
- **CQRS Separation:** Command side publishes events, query side subscribes
- **God-Object Elimination:** No service orchestrates others; events coordinate workflow

**Domain Events Pattern:**
Events represent significant domain occurrences:
- **NoteIndexed:** Single note added/updated in index
- **VaultIndexingComplete:** Full vault scan finished
- **FrontmatterValidated:** Frontmatter passed/failed validation
- **SchemaLoaded:** Schema loaded into PropertyBank
- **SchemasReloaded:** All schemas reloaded

**Event Bus Pattern:**
In-memory pub/sub infrastructure:
- **Async Dispatch:** Events processed asynchronously in goroutines
- **Error Isolation:** Failed handlers don't block other subscribers
- **Type-Based Routing:** Subscribe to specific event types
- **Thread-Safe:** Mutex-protected handler registration

**CQRS via Events:**
```
Command Side (Writes)          Event Bus          Query Side (Reads)
─────────────────────          ─────────          ──────────────────
VaultIndexer                                      QueryService
  └─ Publish(NoteIndexed) ───────→ ───────→ Subscribe & rebuild cache
  └─ Publish(Complete)    ───────→ ───────→ Subscribe & update state

VaultIndexer
  └─ Subscribe to events  ←────────
  └─ Update indices
```

### Event Flow Diagram

```
User Action (CLI)
    ↓
CLICommander.IndexVault()
    ↓
Publish(IndexCommand) → EventBus
    ↓
VaultIndexer (Subscriber)
    ├─ Index notes
    ├─ Publish(NoteIndexed) for each note → EventBus
    │       ↓
    │   VaultIndexer (Subscriber)
    │       └─ Update indices
    │
    └─ Publish(VaultIndexingComplete) → EventBus
            ↓
        QueryService (Subscriber)
            └─ Rebuild in-memory structures
```

### Event Handler Design

```go
// Example: VaultIndexer subscribes to NoteIndexed
func (s *VaultIndexer) handleNoteIndexed(ctx context.Context, event DomainEvent) error {
    noteEvent := event.(*NoteIndexedEvent)

    // Update indices based on indexed note
    if err := s.updateIndices(ctx, noteEvent.Note); err != nil {
        s.log.Error().Err(err).Str("noteID", noteEvent.Note.ID).Msg("failed to update indices")
        return err
    }

    s.log.Debug().Str("noteID", noteEvent.Note.ID).Msg("indices updated")
    return nil
}

// Registration during initialization
func (s *VaultIndexer) Initialize(bus *EventBus) error {
    return bus.Subscribe("NoteIndexed", s.handleNoteIndexed)
}
```

### Risks and Mitigations

**HIGH RISK: Async event processing adds debugging complexity**
- **Impact:** Harder to trace event flow and debug issues
- **Mitigation:** Comprehensive event logging with trace IDs; structured logging
- **Validation:** Integration tests with full event flow tracing

**MEDIUM RISK: Event ordering guarantees**
- **Impact:** Events may be processed out of order
- **Mitigation:** Document event ordering semantics; use synchronous dispatch for critical events
- **Validation:** Concurrency tests with ordering assertions

**LOW RISK: Event overhead performance**
- **Impact:** Event dispatch may add latency
- **Mitigation:** Benchmark to ensure < 5ms overhead; acceptable for decoupling benefits
- **Validation:** Performance tests measuring event overhead
