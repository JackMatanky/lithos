### Architecture Patterns

**Entity Enrichment Pattern:**
Domain entities should be rich with behavior, not anemic data containers. Frontmatter enrichment adds:
- **Validation:** Domain-level schema compliance checking
- **Factory Methods:** NewFrontmatter() constructor with validation
- **Type-Safe Accessors:** GetString(), GetInt(), GetBool() with type assertions
- **Domain Logic:** Business rules encapsulated in entity

**Domain-Driven Design:**
Frontmatter is a value object in the domain layer. It must contain:
- **Invariants:** Schema compliance, required fields
- **Behavior:** Validation, field access, type conversion
- **Immutability:** Once created, frontmatter properties don't change without validation

**Validation Strategy:**
Two-level validation approach:
- **Syntactic:** Adapter validates YAML syntax (parsing)
- **Semantic:** Domain validates schema compliance (Frontmatter.Validate)

### Implementation Notes

**Phase 1: Validation Method**
Add Validate() method to Frontmatter entity. This semantic validation checks schema compliance without depending on external parsers.

**Phase 2: Factory Constructor**
Create NewFrontmatter() constructor that validates on creation. Ensures all Frontmatter instances are valid from construction.

**Phase 3: Type-Safe Accessors**
Add GetString(), GetInt(), GetBool(), etc. methods with type assertions and default value handling. Replaces unsafe map access.

Example accessor signature:
```go
func (f Frontmatter) GetString(key string) (string, bool) {
    value, ok := f.fields[key]
    if !ok {
        return "", false
    }
    str, ok := value.(string)
    return str, ok
}
```
Callers then use `title, ok := frontmatter.GetString("title")` instead of raw map casts.

**Phase 4: Integration**
Update FrontmatterService to use new entity methods. Reduces service complexity by delegating to entity.

### Risks and Mitigations

**LOW RISK: Type assertion panics in accessors**
- **Impact:** Runtime panics if types mismatch
- **Mitigation:** Return (value, bool) tuples; document expected types; validation ensures correct types
- **Validation:** Comprehensive unit tests with type mismatches

**LOW RISK: Validation performance overhead**
- **Impact:** Validation on every Frontmatter creation may slow indexing
- **Mitigation:** Benchmark validation; cache validation results if needed
- **Validation:** Performance tests measuring validation overhead (target < 1ms)
