### Architecture Patterns

**Entity Enrichment Pattern:**
Note entity completes the domain model enrichment started with Frontmatter. Rich domain entities encapsulate:
- **Validation:** Business rule enforcement
- **Delegation:** Convenient frontmatter access methods
- **Factory Construction:** Enforced validation on creation
- **Encapsulation:** Hide implementation details

**Law of Demeter:**
Note provides delegation methods to avoid direct frontmatter access:
```go
// BAD: Violates Law of Demeter
note.Frontmatter.GetString("title")

// GOOD: Delegates through Note
note.GetFrontmatterString("title")
```

**Domain-Driven Design:**
Note is an entity (identity-based) containing Frontmatter value object. It provides:
- **Identity:** Path (vault-relative) uniquely identifies notes
- **Behavior:** Validation, field access
- **Consistency:** Factory ensures valid construction

### Implementation Notes

**Phase 1: Validation Method**
Add Note.Validate() for semantic validation (note-level business rules).

**Phase 2: Factory Constructor**
Create NewNote() constructor enforcing validation at creation.

**Phase 3: Delegation Methods**
Add convenience methods delegating to Frontmatter: HasFrontmatterField(), GetFrontmatterString(), etc. Each helper should return `(value, bool)` or `(value, error)` and use a shared `NoteFieldError` sentinel so callers can distinguish missing data from unexpected type mismatches without panics.

**Phase 4: Service Integration**
Update all services to use Note methods instead of direct field access.

### Risks and Mitigations

**LOW RISK: Delegation method explosion**
- **Impact:** Too many convenience methods clutter API
- **Mitigation:** Only add frequently-used delegations; document when to access Frontmatter directly
- **Validation:** Code review for API clarity

**LOW RISK: Validation complexity**
- **Impact:** Note.Validate() may become complex with many business rules
- **Mitigation:** Extract validation strategies if complexity grows
- **Validation:** Monitor cyclomatic complexity; refactor if > 10
