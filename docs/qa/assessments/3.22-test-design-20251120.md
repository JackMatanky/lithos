# Test Design: Story 3.22

Date: 2025-11-20
Designer: Quinn (Test Architect)

## Test Strategy Overview

- Total test scenarios: 10
- Unit tests: 2 (20%)
- Integration tests: 7 (70%)
- E2E tests: 1 (10%)
- Priority distribution: P0: 8, P1: 2, P2: 0

## Test Scenarios by Acceptance Criteria

### AC1-3: CacheUnitOfWork structure, batching, indexTime propagation

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-UNIT-001 | Unit | P0 | Unit tests ensure `Begin`, `AddWrite`, `AddDelete` mutate internal buffers and propagate identical `indexTime` to both writers. | Pure logic best validated in isolation.

### AC4: Commit sequence (BoltDB first, SQLite second)

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-001 | Integration | P0 | Execute commit with spies to assert BoltDB writer invoked before SQLite writer and both receive same notes/indexTime. | Requires instrumented writers.

### AC5-6: Failure handling and compensating rollback

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-002 | Integration | P0 | Simulate BoltDB failure (expect commit abort + no SQLite writes) and SQLite failure (expect compensating delete in BoltDB). | Multi-adapter behaviour only visible in integration test.

### AC8-10: Rollback APIs (bolt.Tx.Rollback, SQL ROLLBACK, compensating writes)

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-003 | Integration | P0 | Force rollback paths in both storage adapters and verify operations list cleared plus compensating delete occurs. | Validates actual persistence backends.

### AC11-13: VaultIndexer & CLI usage wrapped in UoW with structured errors

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-E2E-001 | E2E | P0 | Run CLI indexing command on fixture vault, asserting VaultIndexer uses UoW (log hook) and user-visible errors include transaction context. | Requires full CLI stack to confirm orchestration.

### AC14: Unit tests for Begin/Commit/Rollback lifecycle

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-UNIT-002 | Unit | P1 | Ensure `internal/app/vault/unit_of_work_test.go` covers lifecycle transitions and mutex behaviour, achieving ≥85% coverage. | Confirms RED/GREEN test discipline.

### AC15: Integration test for SQLite failure rollback

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-004 | Integration | P0 | Inject SQLite error mid-commit and assert BoltDB entries removed plus error propagated. | Explicitly satisfies AC15 scenario.

### AC16: Integration test for BoltDB failure prevention

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-005 | Integration | P0 | Force BoltDB failure (e.g., file permissions) and assert SQLite writer never invoked while error surfaces. | Covers AC16 guardrail.

### AC7 & AC17: Transaction isolation and concurrency safety

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-006 | Integration | P0 | Launch multiple goroutines running Begin/Add*/Commit and confirm mutex prevents interleaving plus no races (run with `-race`). | Validates concurrent behaviour beyond unit scope.

### AC18: Performance overhead <10%

| ID | Level | Priority | Test | Justification |
| --- | --- | --- | --- | --- |
| 3.22-INT-007 | Integration | P1 | Benchmark batch writes with/without UoW on fixture vault; assert overhead <10% for typical workload. | Requires integrated benchmark harness.

## Risk Coverage

- Dual-write inconsistency mitigated via scenarios 3.22-INT-001/002/003.
- Concurrency hazards mitigated via 3.22-INT-006.
- Performance regression risk mitigated via 3.22-INT-007.

## Recommended Execution Order

1. 3.22-UNIT-001, 3.22-UNIT-002
2. 3.22-INT-001 through 3.22-INT-003
3. 3.22-INT-004 and 3.22-INT-005 (failure cases)
4. 3.22-INT-006 (race) and 3.22-INT-007 (performance)
5. 3.22-E2E-001 (CLI verification)
