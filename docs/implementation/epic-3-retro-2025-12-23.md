## What Didn't Go Well (Challenges)

### Technical Challenges
- **Course Correction Scope**: Revisiting "completed" work was painful but necessary

- **Dual-Write Complexity**: Unit of Work pattern implementation took longer than estimated

- **Performance Ambitions**: Some initial performance targets were more aggressive than realistic

### Process Challenges
- **Architectural Assumptions**: Early hybrid storage assumptions proved incorrect, requiring foundation rework
- **Scope Creep**: Course correction added significant unplanned work to existing timeline
- **Testing Overhead**: Event-driven architecture increased integration testing complexity
- **Knowledge Transfer**: Shift from anemic to rich domain models required conceptual rethinking

### Systemic Issues Identified
- **Early Architectural Validation**: Need for architectural spikes before committing to large epics
- **Incremental vs. Foundational Changes**: Some changes required rethinking entire layers
- **Technical Debt Recognition**: Importance of addressing architectural debt before feature work
- **Performance Benchmarking**: Need for realistic performance expectations and early validation

---

## Key Insights & Learnings

### 1. Course Corrections Are Worth the Investment
**Learning:** Major architectural issues discovered during development should be addressed immediately, even if it means revisiting "completed" work. The alternative (shipping with known issues) creates worse technical debt.

**Impact:** Epic 3's course correction prevented architectural problems from propagating to Epic 4 and beyond.

### 2. Domain Modeling Matters
**Learning:** Rich domain entities with behavior methods create more maintainable and testable code than anemic data structures. The investment in Stories 3.24-3.25 paid dividends in code clarity and testability.

**Impact:** Epic 4 will build on these enriched entities for schema validation logic.

### 3. Hybrid Storage Patterns Are Powerful but Complex
**Learning:** The BoltDB+SQLite hybrid approach successfully solved performance scaling, but the dual-write coordination requires careful design and thorough testing.

**Impact:** Established patterns that can be reused for other performance-critical features.

### 4. Event-Driven Architecture Improves Decoupling
**Learning:** Domain events with EventBus pattern significantly improved service decoupling and testability, though it increased initial complexity.

**Impact:** Foundation laid for scalable, maintainable event-driven features in future epics.

### 5. Performance Benchmarking Should Be Early and Realistic
**Learning:** Performance targets should be validated early with realistic data sets. Epic 3's performance achievements required careful tuning of storage layers.

**Impact:** Better performance planning for future epics.
